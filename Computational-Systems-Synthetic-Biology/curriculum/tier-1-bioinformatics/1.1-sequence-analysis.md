# 1.1 Sequence Analysis

The computational layer closest to raw biological data. Sequence comparison is the oldest and most pervasive problem in bioinformatics — nearly everything else builds on it.

---

## Pairwise Sequence Alignment

### The Alignment Problem
Given two sequences, find the arrangement that maximizes similarity while accounting for gaps (insertions and deletions). This is a prerequisite for:
- Identifying homologous genes across species
- Mapping sequencing reads to a reference genome
- Detecting conserved functional motifs
- Predicting protein structure via comparative modeling

### Edit Distance
- Minimum number of single-character edits (insertions, deletions, substitutions) to transform one string into another
- Levenshtein distance: all three operations have cost 1
- Foundation for all alignment scoring schemes

### Dynamic Programming Alignments

**Needleman-Wunsch (Global Alignment)**
- Aligns two sequences end-to-end
- Initialization: gap penalties on both edges
- Recursion: score = max(match/mismatch from diagonal, gap from left, gap from top)
- Traceback from bottom-right to top-left
- Time: O(nm), Space: O(nm) — can reduce space to O(min(n,m)) with divide-and-conquer
- Use when: sequences are expected to be similar across their full length

**Smith-Waterman (Local Alignment)**
- Finds the best-scoring local region
- Same recursion but floor at zero: suboptimal alignments are reset
- Traceback starts from the highest-scoring cell
- Use when: looking for conserved domains within longer sequences

**Gap Penalty Models**
- Linear: gap cost = d × gap_length — simple but biologically unrealistic
- Affine: gap cost = gap_open + (gap_length - 1) × gap_extend — better models biology (one indel event usually opens a run of gaps)
- Gotoh algorithm: extends DP to handle affine penalties in O(nm)

### Substitution Matrices

**PAM (Point Accepted Mutation) Matrices**
- Derived from closely related protein pairs
- PAM1: 1 accepted mutation per 100 residues
- PAM250: extrapolated to more divergent sequences
- Based on evolutionary model: good for closely related sequences

**BLOSUM (BLOcks SUbstitution Matrix)**
- Derived directly from ungapped alignment blocks in BLOCKS database
- BLOSUM62: derived from alignments with ≥62% identity — the standard default
- BLOSUM50: derived from more divergent alignments — use for more distant relatives
- BLOSUM80: for closely related sequences
- Rule: use higher BLOSUM number for similar sequences, lower for divergent

**Nucleotide Substitution**
- Simple identity matrices for exact matching
- EDNAFULL: matches and mismatches among IUPAC ambiguity codes
- For protein-coding regions, often better to align translated sequence

### Heuristic Alignment: BLAST

**Why Heuristics?**
- O(nm) DP is too slow for searching billions of nucleotides
- BLAST achieves near-Smith-Waterman sensitivity at 100–1000× speed

**BLAST Algorithm (seed-and-extend)**
1. Break query into words of length W (11 for blastn, 3 for blastp)
2. Find all words scoring above threshold T against substitution matrix
3. Search database for exact matches to these words
4. Extend matching words in both directions while score > X-drop threshold
5. Report alignments with E-value below threshold

**E-value and Statistics**
- E-value: expected number of alignments with this score by random chance
- E-value = Kmnе^(-λS) where S is the alignment score
- E-value < 1e-5: typically significant; E-value < 1e-10: high confidence homology
- Distinguish from p-value: same concept, different normalization

**BLAST Variants**
- `blastn`: nucleotide query vs. nucleotide database
- `blastp`: protein query vs. protein database
- `blastx`: nucleotide query (all 6 frames translated) vs. protein database
- `tblastn`: protein query vs. translated nucleotide database
- `tblastx`: all 6 frames vs. all 6 frames
- `megablast`: optimized for highly similar sequences (read mapping to genome)
- DIAMOND: 10–100× faster than BLAST for protein search, similar sensitivity

**PSI-BLAST (Position-Specific Iterated BLAST)**
- Builds position-specific scoring matrix (PSSM) from initial alignment results
- Iteratively searches with updated PSSM — finds distantly related sequences
- Use for detecting remote homologs

## Multiple Sequence Alignment

### Why Multiple Alignment?
- Reveals conserved residues across many species (often functionally critical)
- Input to phylogenetic analysis
- Builds profiles for database searching (HMMs)
- Identifies co-evolving positions (covariation analysis → structure prediction)

### Progressive Methods
- Build guide tree from pairwise distances
- Align sequences from most-similar to most-divergent
- **ClustalW**: historic standard; uses distance-based guide tree
- **MUSCLE**: faster, iterative refinement; generally preferred over ClustalW
- **MAFFT**: multiple strategies; FFT-NS-2 (fast), L-INS-i (accurate, local alignment)

### Iterative Methods
- Alternately realign subgroups and the full alignment
- Improves over progressive alignment by avoiding early errors
- MAFFT L-INS-i, MUSCLE: both use iterative refinement

### Alignment Quality
- Sum-of-pairs score
- Column score
- Visual inspection with alignment editors (Jalview, AliView)
- Watch for: over-gapping, spurious conservations, misaligned regions

### Profile HMMs
- Profile Hidden Markov Models represent a multiple alignment as a probabilistic model
- States: match (M), insert (I), delete (D)
- Emission probabilities at each position
- Transition probabilities between states
- **HMMER**: the standard tool for profile HMM search
  - `hmmbuild`: build profile from alignment
  - `hmmsearch`: search profile against sequence database
  - `hmmscan`: search sequence against profile database (Pfam)
- Pfam database: ~19,000 protein family profiles
- HHMER: pairwise profile-vs-profile alignment — the most sensitive method for remote homology

## File Formats in Depth

### FASTA
```
>sequence_id description
ATGCGTAGCTAGCTAGCTAGCTAGCGATCGATCGATCG
ATCGATCGATCGATCGATCGATCG
```
- First line: header starting with `>`
- Subsequent lines: sequence (usually 60–80 chars/line)
- No quality information

### FASTQ
```
@read_id description
ATGCGTAGCTAGCTAGCTAGCTAGCGATCGATCGATCG
+
IIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIII
```
- Line 1: `@` + read ID
- Line 2: sequence
- Line 3: `+` (optionally repeat header)
- Line 4: quality scores (Phred+33 encoding)
- Phred quality: Q = -10 log₁₀(P_error); Q30 = 0.1% error rate

### SAM/BAM
- SAM: tab-delimited text; BAM: binary equivalent (10–15× smaller)
- 11 mandatory fields: QNAME, FLAG, RNAME, POS, MAPQ, CIGAR, RNEXT, PNEXT, TLEN, SEQ, QUAL
- FLAG field encodes: paired, properly paired, unmapped, reverse strand, etc.
- CIGAR string: M(match), I(insert), D(deletion), N(intron), S(soft clip), H(hard clip)
- Header section: @SQ (sequence names/lengths), @RG (read groups), @PG (programs)
- Tools: samtools (view, sort, index, flagstat, mpileup)

### VCF
- Header lines: ##fileformat, ##INFO, ##FORMAT, ##FILTER, ##contig
- Data columns: CHROM, POS, ID, REF, ALT, QUAL, FILTER, INFO, FORMAT, sample_genotypes
- INFO field: allele frequency (AF), depth (DP), strand bias, etc.
- Genotype field (GT): 0/0 homref, 0/1 het, 1/1 homalt, 0/2 het with second alt
- Tools: bcftools, GATK, VEP (functional annotation)

### BED / GFF3 / GTF
- BED: 3 required fields (chrom, start, end) + optional (name, score, strand, ...)
  - 0-based, half-open coordinates: chr1:0-100 = first 100 bases
- GFF3: 9 fields including ID/Parent attributes; 1-based coordinates
- GTF: similar to GFF2; gene and transcript features; used by STAR, featureCounts
- Tools: bedtools (intersect, merge, subtract, coverage, getfasta)

## Short-Read Mapping & Assembly

### Read Mapping

**The Mapping Problem**
- Millions to billions of reads, each 50–300 bp
- Reference genome: 3 Gb (human) to hundreds of Gb
- Must handle: mismatches (sequencing errors + SNPs), indels, repetitive regions, splicing

**Burrows-Wheeler Transform (BWT)**
- Reversible string transformation that enables compressed FM-index
- FM-index allows O(m) search for pattern of length m
- Used by BWA, Bowtie2 for ultra-fast alignment

**Key Aligners**
- **BWA-MEM2**: gapped alignment, handles indels, standard for genomic DNA
- **Bowtie2**: fast, good for ChIP-seq, ATAC-seq (shorter-read sensitive applications)
- **STAR**: splice-aware alignment for RNA-seq; builds junction database; requires more RAM
- **HISAT2**: splice-aware, lower memory than STAR; HISAT graph index
- **minimap2**: long reads (Oxford Nanopore, PacBio), structural variant discovery

**Mapping Quality**
- MAPQ: -10 log₁₀(P_mapping_wrong); MAPQ 60 = uniquely mapped
- Multi-mapping reads: assigned to all locations, or randomly, or filtered out
- Repetitive regions are inherently difficult — satellite DNA, segmental duplications

### Genome Assembly

**The Assembly Problem**
- Given millions of short, overlapping reads, reconstruct the original sequence
- No read covers a full chromosome (except for small viruses/organelles)
- Complication: repetitive elements longer than read length are unresolvable

**Overlap-Layout-Consensus (OLC)**
- Build overlap graph: nodes = reads, edges = overlapping reads
- Find Hamiltonian path (NP-hard; heuristic approaches used)
- Consensus sequence from aligned reads
- Good for long reads: Celera Assembler (historic), Flye, Canu

**de Bruijn Graph**
- Decompose reads into k-mers
- Nodes = (k-1)-mers, edges = k-mers
- Find Eulerian path (efficient, polynomial time)
- Repeats longer than k are unresolvable
- Widely used for short reads: SPAdes, Velvet
- Key insight: Eulerian path ≠ Hamiltonian path — this is why de Bruijn graphs are tractable

**K-mer Coverage**
- Coverage (C) = (number_reads × read_length) / genome_size
- K-mer frequency histogram: main peak at C, secondary peaks at 2C (diploid), errors at low frequency
- Estimate genome size from k-mer histogram: genome_size ≈ total_kmers / peak_coverage

**Assembly Quality Metrics**
- N50: length such that contigs ≥ N50 contain 50% of total assembly
- NG50: like N50 but relative to estimated genome size
- BUSCO completeness: fraction of expected single-copy orthologs present, complete, and fragmented
- Long-range accuracy: QV score from read alignment, misassembly rate

**Long-Read Assembly**
- PacBio HiFi: 10–25 kb reads, <0.1% error rate; best accuracy
- Oxford Nanopore: up to megabases, 5–15% raw error rate (improving)
- Assemblers: Flye (nanopore/PacBio CLR), Hifiasm (HiFi), WTDBG2
- Hybrid assembly: combine short reads (accuracy) + long reads (contiguity)

## Practical Tools Reference

| Task | Tool | Notes |
|---|---|---|
| Pairwise alignment | EMBOSS Needle/Water | DP implementation |
| Database search | BLAST, DIAMOND | DIAMOND for speed |
| Multiple alignment | MAFFT L-INS-i | Most accurate |
| Profile HMM | HMMER | Pfam, Pfam_scan |
| Short read mapping | BWA-MEM2 | DNA; Bowtie2 for ChIP |
| RNA-seq mapping | STAR, HISAT2 | STAR for accuracy |
| Long read mapping | minimap2 | Universal |
| Short read assembly | SPAdes | Most versatile |
| Long read assembly | Hifiasm (HiFi) / Flye | Format-dependent |
| BAM manipulation | samtools | Sort, index, flagstat |
| VCF manipulation | bcftools | Filter, annotate, merge |
| Interval operations | bedtools | Intersect, merge, coverage |
| Quality control | FastQC, MultiQC | Always do this first |
| Trimming | fastp, Trimmomatic | fastp preferred (faster) |
