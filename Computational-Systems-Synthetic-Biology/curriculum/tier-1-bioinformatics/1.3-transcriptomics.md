# 1.3 Transcriptomics

Measuring gene expression at scale — the most commonly applied omics layer in biology.

---

## Bulk RNA-seq

### Experimental Design
Before running a single sample, the experimental design determines what you can conclude.

**Replicates**
- Biological replicates: independent biological samples (different mice, different cultures)
- Technical replicates: same RNA processed multiple times — generally unnecessary with modern protocols
- Rule: 3 biological replicates minimum; 6+ for detecting moderate effects
- Power analysis: use `RNASeqPower` or `pwr` in R to estimate needed sample size

**Sequencing Depth**
- 10–20 million mapped reads: sufficient for differential expression of highly expressed genes
- 30–50 million: for detecting lowly expressed genes
- Deeper coverage needed for: alternative splicing analysis, long non-coding RNA
- Always sequence to saturation for novel transcript discovery

**Library Types**
- Unstranded: do not preserve information about which strand was transcribed
- Stranded (dUTP, ligation): preserves strand information — required for antisense RNA, overlapping genes
- Poly-A selected: enriches for mRNA, depletes rRNA — most common
- Ribosomal depletion (ribo-minus): preserves non-polyadenylated RNA

### The RNA-seq Pipeline

**Step 1: Quality Control**
- `FastQC`: per-base quality scores, GC content, adapter contamination, overrepresented sequences
- `MultiQC`: aggregate QC across all samples in one report
- Flag: Q < 30 at 3' end, adapter content >10%, unusual GC distribution

**Step 2: Trimming**
- `fastp`: fast, all-in-one; adapter detection + quality trimming + QC report
- `Trimmomatic`: still widely used; configure adapters for your library prep kit
- Conservative trimming: only remove clear adapter contamination and very low quality tails

**Step 3: Alignment**
- `STAR`: splice-aware; 2-pass mode for improved junction detection
  - First pass: generate splice junction database
  - Second pass: align using discovered junctions
  - High RAM requirement (~30 Gb for human)
- `HISAT2`: lower RAM (~8 Gb for human); uses genome graph index with SNPs

**Step 4: Quantification**

*Alignment-based*
- `featureCounts` (Subread): counts reads per gene from BAM + GTF
- `HTSeq-count`: similar to featureCounts, slower
- Key parameter: how to handle multi-mapping reads (--primary, --fraction)

*Pseudo-alignment (faster, no BAM)*
- `Salmon`: probabilistic model, corrects for GC bias and positional bias; transcript-level
- `kallisto`: k-mer equivalence classes; very fast; transcript-level
- Use with `tximport` in R to aggregate to gene level for DEseq2/edgeR

**Step 5: Differential Expression Analysis**

**DESeq2**
- Negative binomial model: counts are overdispersed relative to Poisson
- Size factors: normalize for library size using median-of-ratios method
- Dispersion estimation: shares information across genes using empirical Bayes
- Wald test for pairwise comparisons; LRT for complex designs
- Shrinkage of log2 fold changes: `lfcShrink()` with ashr or apeglm
- Output: log2FoldChange, p-value, padj (BH-corrected)
- Significant: |log2FC| > 1 AND padj < 0.05 (typical thresholds)

**edgeR**
- Also negative binomial; TMM normalization (trimmed mean of M-values)
- Two approaches: exact test (simple two-group) or quasi-likelihood F-test (complex designs)
- `glmQLFit()` + `glmQLFTest()`: recommended for complex designs
- Handles very small sample sizes slightly differently than DESeq2

**limma-voom**
- Transform counts to log-CPM with precision weights
- Uses linear modeling (limma): most flexible for complex designs
- `voom()` + `lmFit()` + `eBayes()` + `topTable()`
- Preferred for: very large datasets, complex factorial designs, batch correction

**Normalization Methods**
- Raw counts: use for DESeq2/edgeR input
- CPM (Counts Per Million): library size normalization only — do not compare between genes
- RPKM/FPKM: normalize by length and library size — do not use for cross-sample comparison
- TPM (Transcripts Per Million): normalize by length first, then library size — comparable across samples
- Rule: use TPM for visualization and cross-sample comparison; raw counts for DE testing

**Step 6: Downstream Analysis**
- Gene Ontology (GO) enrichment: clusterProfiler, topGO; Fisher's exact test or KS test
- KEGG pathway enrichment: clusterProfiler::enrichKEGG
- Gene Set Enrichment Analysis (GSEA): ranked list approach, MSigDB gene sets
- Heatmaps: pheatmap, ComplexHeatmap; use normalized, variance-stabilized counts (VST)
- PCA: check sample clustering, detect outliers, batch effects
- Volcano plots: -log₁₀(padj) vs. log2FC; label significant genes

## Single-Cell RNA-seq

### Why Single Cells?
Bulk RNA-seq averages across thousands of cells. scRNA-seq reveals:
- Cell type composition and proportions
- Cell-type-specific differential expression
- Developmental trajectories and differentiation
- Rare cell types hidden in bulk data
- Intratumoral heterogeneity

### Technology Overview

**Droplet-Based (10x Genomics Chromium)**
- Cells partitioned into nanoliter droplets with barcoded beads
- Each cell gets a unique 16-bp cell barcode
- Each transcript gets a unique 10-12 bp UMI (Unique Molecular Identifier)
- Throughput: hundreds to tens of thousands of cells per run
- Coverage: ~1,000–3,000 genes detected per cell at standard depth

**Plate-Based (Smart-seq2, Smart-seq3)**
- Single cells sorted into 384-well plates
- Full-length transcript coverage (useful for isoform analysis)
- Lower throughput (~384 cells/run)
- Higher sensitivity per cell but higher cost per cell

**Cell Ranger (10x preprocessing)**
- `cellranger count`: STARsolo alignment, barcode/UMI counting
- Outputs: filtered_feature_bc_matrix (genes × cells)
- Key QC outputs: cells detected, median genes per cell, saturation

### The scRNA-seq Analysis Pipeline (Seurat / Scanpy)

**Step 1: Quality Control**
- Filter cells: min_genes (200), max_genes (5000 for doublet detection), max % mitochondrial reads (20%)
- High mitochondrial %: dead or dying cells
- High gene count + high UMI: potential doublets (two cells in one droplet)
- Doublet detection: DoubletFinder (Seurat), Scrublet, SOLO (Scanpy)

**Step 2: Normalization**
- Library size normalization: multiply each cell by 10,000/total_counts → CPM-like
- Log transformation: log1p(CPM)
- SCTransform (Seurat): regularized negative binomial regression; preferred for 10x data

**Step 3: Feature Selection**
- Highly variable genes (HVGs): identify genes with high variability across cells
- Typically 2,000–5,000 HVGs
- Used for all subsequent analysis to reduce noise

**Step 4: Dimensionality Reduction**
- PCA: linear; use top 30–50 PCs
- UMAP: non-linear; preserves local structure; standard for visualization
  - Key parameters: n_neighbors, min_dist — affect topology of the embedding
- t-SNE: older alternative; less stable than UMAP for large datasets

**Step 5: Clustering**
- Graph-based (Louvain/Leiden): k-nearest neighbor graph → community detection
- Resolution parameter: higher = more clusters
- Leiden preferred over Louvain for quality
- Validate clusters: they should correspond to biological cell types, not technical artifacts

**Step 6: Cell Type Annotation**
- Manual annotation: examine marker gene expression per cluster
- Canonical markers: CD3D/CD3E (T cells), CD14 (monocytes), MS4A1 (B cells), etc.
- Automated: scType, SingleR, CellTypist — reference-based annotation
- Verify: markers should be cluster-specific, not bleed across

**Step 7: Differential Expression**
- Pseudo-bulk approach: aggregate single cells to sample-level, use DESeq2/edgeR
- Per-cluster Wilcoxon rank-sum tests for marker gene finding
- Avoid inflated p-values from treating cells as independent observations

### Trajectory and Pseudotime Analysis
- Order cells along developmental continuum
- Pseudotime: inferred relative position in developmental progression
- **Monocle3**: principal graph, learns trajectory topology; handles complex branching
- **PAGA (Scanpy)**: partition-based graph abstraction; robust for complex topologies
- **scVelo**: RNA velocity from spliced/unspliced read ratio; direction of differentiation

### RNA Velocity
- Unspliced (pre-mRNA) and spliced mRNA ratios predict cell state dynamics
- High unspliced/spliced ratio: gene being actively transcribed → will increase
- Low ratio: gene being degraded → will decrease
- Vectors in UMAP space show predicted direction of state change
- Tools: scVelo, velociraptor (R)

### Cell-Cell Communication
- Ligand-receptor interaction databases: CellChat, CellPhoneDB, NicheNet
- Quantify signaling probability based on expression of ligand + receptor in sender + receiver cells
- Identify dominant signaling pathways and intercellular communication networks

### Spatial Transcriptomics
- Gene expression measured with spatial coordinates preserved
- **10x Visium**: 55 µm spots, ~5–10 cells/spot; not single-cell resolution
- **Slide-seq v2**: ~10 µm beads; near single-cell resolution
- **MERFISH/seqFISH+**: in situ sequencing; single-cell resolution, hundreds to thousands of genes
- Integration with scRNA-seq: deconvolve cell types within Visium spots using reference
- Tools: Seurat (SpatiallyVariableFeatures), Squidpy (Python), RCTD (cell type deconvolution)

## Other RNA-seq Applications

### Alternative Splicing Analysis
- rMATS: detects five types of alternative splicing (SE, MXE, A3SS, A5SS, RI)
- SUPPA2: fast, transcript probability-based
- LeafCutter: intron cluster-based; detects splicing quantitative trait loci (sQTLs)
- Key output: PSI (Percent Spliced In) for each event, compared between conditions

### Small RNA-seq (miRNA, piRNA, siRNA)
- Short reads (18–25 nt) require special handling
- miRDeep2: identifies miRNA from collapsed reads
- miRBase: miRNA annotation database
- Target prediction: TargetScan, miRanda

### Long Non-coding RNA Analysis
- LncRNA: >200 nt, no substantial ORF
- GENCODE lncRNA annotations
- lncRNA function prediction from: co-expression, sub-cellular localization (ENCODE SPRITE), CRISPR screens

### Ribosome Profiling (Ribo-seq)
- Sequence ribosome-protected mRNA fragments (28–30 nt)
- Maps active translation genome-wide
- Identifies translated ORFs (including upstream ORFs, downstream ORFs)
- Translation efficiency = Ribo-seq RPKM / RNA-seq RPKM
- Tools: RibORF, ribotricer, RiboWaltz

## Common Analysis Pitfalls

| Pitfall | Consequence | Fix |
|---|---|---|
| Not checking batch effects | False DE genes from run/batch confounding | PCA colored by batch; ComBat-seq or include batch in model |
| Using RPKM for cross-sample comparison | Wrong conclusions about relative expression | Use TPM for visualization |
| Treating scRNA-seq cells as independent for DE | Inflated p-values, many false positives | Pseudo-bulk + DESeq2 |
| Not running FastQC | Missing quality issues that invalidate downstream results | Always QC first |
| Clustering at wrong resolution | Merged cell types or over-split clusters | Try multiple resolutions; validate with known markers |
| UMAP as ground truth | UMAP distorts global distances | Use for visualization only; validate distances with PCA |
