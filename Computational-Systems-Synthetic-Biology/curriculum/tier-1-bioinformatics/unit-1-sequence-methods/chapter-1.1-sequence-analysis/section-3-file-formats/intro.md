# Section 3: Sequence File Formats

Before algorithms, there is data. And before data can be analyzed, it must be read correctly.

This section covers the five file formats that appear in nearly every sequencing-based analysis: FASTA for sequences, FASTQ for raw reads with quality scores, SAM/BAM for aligned reads, VCF for variants, and BED/GFF3/GTF for genomic feature annotations. These formats are the lingua franca of bioinformatics. Whether you are running a variant calling pipeline, analyzing RNA-seq data, interpreting ChIP-seq peaks, or computing evolutionary distances, your data flows between tools through these formats.

You might be tempted to treat this as reference material — something to look up when you need it rather than understand deeply. That would be a mistake. The most common sources of silent errors in bioinformatics pipelines are not algorithmic misunderstandings; they are format misunderstandings. Using the wrong coordinate system (BED is 0-based, GFF3 is 1-based), misinterpreting a FLAG field in a SAM file, failing to recognize that a FASTQ file is already gzip-compressed — these mistakes produce wrong answers that look perfectly correct, with no error messages and no obvious warnings.

The formats in this section also encode biological meaning that is worth understanding explicitly. Phred quality scores in FASTQ files are logarithmic: Q20 means 1% error probability, Q30 means 0.1%, a ten-fold difference that matters enormously for variant calling thresholds. The FLAG field in SAM/BAM is a bitwise integer that encodes twelve different properties of each read simultaneously — understanding it is the difference between correctly filtering duplicate reads and accidentally discarding half your data. The genotype encoding in VCF (the `0/1`, `1/1` notation) reflects not just which alleles are present but whether they are phased, with real consequences for downstream haplotype analysis.

Each subsection follows the same structure: what the format represents biologically, its precise specification, how to parse and manipulate it programmatically, and the common pitfalls that trap researchers who treat it as a black box. By the end of this section, you should be able to inspect any of these files at the command line, understand what each field means, and write correct code to read and write them — without needing to look up the specification.
