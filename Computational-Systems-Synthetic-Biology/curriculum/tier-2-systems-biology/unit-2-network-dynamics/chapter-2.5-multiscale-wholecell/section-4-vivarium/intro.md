The Karr 2012 whole-cell model was a tour de force. It was also, from a software engineering perspective, a monolith: every submodel was glued to every other through custom integration code, written specifically for *Mycoplasma genitalium* by a single dedicated team. If you wanted to add a new process — say, an updated model of ribosome kinetics based on new structural data — you had to understand the entire codebase, modify the shared state management, and hope you didn't break the fifteen other submodels that depend on protein synthesis rates. If you wanted to reuse the transcription submodel in a different context, you essentially had to transplant a vital organ: it would arrive tangled in the connective tissue of the whole.

This is the software problem that Vivarium was designed to solve. Not by building a better whole-cell model, but by building better infrastructure for multiscale biology generally.

This section covers Vivarium, a compositional simulation framework published in *eLife* in 2022. The core idea is deceptively simple: separate the definition of each biological process from the specification of how processes communicate. A Process in Vivarium is a self-contained Python class with explicit input and output ports. It has no knowledge of any other process; it only reads from and writes to named locations in a shared hierarchical store. The topology — the wiring diagram that connects process ports to store locations — is specified separately and can be changed without touching any process code. Adding a new submodel means writing one new class and adding a few lines of wiring. Removing it is equally clean.

What makes this more than a software convenience is the hierarchical composition feature: a collection of processes can itself be wrapped and treated as a single Process from the perspective of a higher-level simulation. This is the principled realization of multiscale modeling — a cell model becomes an agent in a colony model; a colony model becomes a community in an ecology model. The nesting can go as deep as the biology requires, and each level remains independently testable and reusable.

You will work through the core Vivarium abstractions — Process, Store, Composite, and topology — with concrete code examples that trace the path from a minimal enzyme kinetics model to a coupled cell colony simulation. By the end of this section, you should understand both what Vivarium does and why the compositional architecture it embodies is the right framework for building complex multiscale models incrementally, in teams, with reusable parts.
