## Numerical Methods for ODEs

### Why ODE Solvers Matter

A biological ODE model is only as good as its solver. The wrong solver gives:
- Wrong answers (numerical instability)
- Correct answers but extremely slowly (inefficiency)
- Missed behavior (too large a step size)

### Integration Methods

**Explicit Methods (forward-looking)**

*Euler method*: x(t+h) = x(t) + h·f(x(t))
- Simplest possible; first-order accurate
- Step size must be small for stability: h < 2/λ_max where λ_max is largest eigenvalue
- Only for learning; never use for real problems

*Runge-Kutta 4 (RK4)*:
- Four function evaluations per step; fourth-order accurate
- Fixed step size
- Works for non-stiff problems

*Dormand-Prince (RKDP / RK45)*:
- Adaptive step size: compare 4th and 5th order solutions to estimate error
- Automatically reduces h when error large; increases h when error small
- Default in SciPy `solve_ivp(method='RK45')`, MATLAB `ode45`
- Use for: smooth, non-stiff systems

### Stiffness

**What is stiffness?**

A system is stiff if different components evolve on very different timescales:
- Fast transients (enzyme-substrate complex formation, signaling second messengers)
- Slow dynamics (gene expression, growth)
- Ratio of fastest to slowest timescale: stiffness ratio; can be 10^6 or more

**Why stiffness is a problem:**
- Explicit methods: stability requires h < 2/λ_max
- λ_max is determined by the *fastest* process
- Must take tiny steps throughout even when fast dynamics have settled
- Result: millions of steps to simulate a slow process

**Identifying stiffness:**
- Explicit solver gets very slow or crashes
- Jacobian eigenvalues span many orders of magnitude
- Biological clue: mixing fast (ns-µs) and slow (minutes-hours) processes

### Stiff Solvers (Implicit Methods)

Implicit methods solve for x(t+h) using the value at t+h itself:
x(t+h) = x(t) + h·f(x(t+h))  [backward Euler]

This requires solving a (nonlinear) system of equations per step — more expensive per step, but stable for any step size.

**LSODA (Livermore Solver for ODEs with Automatic method switching)**
- Automatically switches between non-stiff (Adams) and stiff (BDF) methods
- Default for biological systems
- SciPy: `solve_ivp(method='LSODA')`

**BDF (Backward Differentiation Formula)**
- Variable order (1–5); variable step size
- Industry standard for stiff systems
- SciPy: `solve_ivp(method='BDF')`; MATLAB: `ode15s`

**Radau**
- Implicit Runge-Kutta; very accurate for stiff problems
- SciPy: `solve_ivp(method='Radau')`; MATLAB: `ode23s`

**Julia: DifferentialEquations.jl**
- Best-in-class: Tsit5 (non-stiff), Rosenbrock23 (stiff), CVODE_BDF (large stiff systems)
- Automatic solver selection based on problem analysis
- 2–10× faster than SciPy for equivalent problems

```julia
using DifferentialEquations

function repressilator!(du, u, p, t)
    α, α₀, n, β = p
    m1, m2, m3, p1, p2, p3 = u
    du[1] = -m1 + α/(1 + p3^n) + α₀
    du[2] = -m2 + α/(1 + p1^n) + α₀
    du[3] = -m3 + α/(1 + p2^n) + α₀
    du[4] = -β*(p1 - m1)
    du[5] = -β*(p2 - m2)
    du[6] = -β*(p3 - m3)
end

u0 = [0.1, 0.2, 0.3, 0.1, 0.2, 0.3]
tspan = (0.0, 200.0)
p = [100.0, 1e-4, 2.0, 1.0]  # α, α₀, n, β
prob = ODEProblem(repressilator!, u0, tspan, p)
sol = solve(prob, Tsit5(), reltol=1e-8, abstol=1e-10)
```

### Jacobian Provision

Stiff solvers require the Jacobian matrix J_ij = ∂f_i/∂u_j.
- Can be approximated by finite differences (automatic but slow)
- Better: provide analytically or use automatic differentiation
- Julia: ForwardDiff.jl computes exact Jacobian automatically
- Python: JAX `jit` + `jacfwd` or `jacrev`

## Numerical Methods for PDEs

### Finite Difference Method

Discretize space into grid with spacing Δx; approximate derivatives:
```
∂u/∂x ≈ (u[i+1] - u[i-1]) / (2Δx)    [central difference]
∂²u/∂x² ≈ (u[i+1] - 2u[i] + u[i-1]) / Δx²
```

Stability for diffusion equation: Δt ≤ Δx²/(2D)  (explicit)

**Method of lines**: discretize space → system of ODEs in time → use ODE solver
```python
import numpy as np
from scipy.integrate import solve_ivp

def reaction_diffusion(t, u_flat, D, nx, dx, f):
    u = u_flat.reshape(nx)
    du = np.zeros_like(u)
    # Interior points
    du[1:-1] = D * (u[2:] - 2*u[1:-1] + u[:-2]) / dx**2 + f(u[1:-1])
    # Boundary conditions (no-flux)
    du[0] = du[1]
    du[-1] = du[-2]
    return du.flatten()
```

### Finite Element Method (FEM)

- Irregular meshes: handle complex geometries
- FEniCS (Python): `from fenics import *`
- COMSOL: commercial, widely used in industry and academia
- Biologically: cell morphology, tissue geometries

### Spectral Methods

- Represent solution as Fourier or Chebyshev series
- Exponential convergence for smooth solutions
- Dealiasing required for nonlinear terms
- SciPy FFT, Dedalus (Python): astrophysics-grade but useful for Turing patterns

## Optimization

### Unconstrained Optimization

**Gradient Descent**
- Move in direction of negative gradient: θ ← θ - α∇J(θ)
- Learning rate α: too large → overshoots; too small → slow
- Stochastic (SGD): use mini-batch of data for each step
- Adam optimizer: adaptive learning rates per parameter; dominant in ML

**Quasi-Newton Methods**
- Approximate Hessian using gradient history (BFGS, L-BFGS-B)
- Much faster than gradient descent for smooth objectives
- L-BFGS-B: memory-efficient; handles bound constraints
- SciPy: `scipy.optimize.minimize(method='L-BFGS-B')`
- Use for: ODE parameter estimation, protein energy minimization

**Nelder-Mead Simplex**
- Gradient-free; uses function evaluations only
- Works for: noisy objectives, non-differentiable functions
- Slow for high-dimensional problems (>10 parameters)
- SciPy: `scipy.optimize.minimize(method='Nelder-Mead')`

### Global Optimization

**Simulated Annealing**
- Metropolis criterion: accept uphill moves with probability e^(-ΔE/T)
- T decreases ("cools") over time → probability of uphill moves decreases
- Guaranteed to find global optimum (in infinite time)
- SciPy: `scipy.optimize.dual_annealing`

**Differential Evolution**
- Population of candidate solutions
- Combine (mutate + crossover) members; keep better
- Robust; works for: 10–100 dimensional parameter spaces
- SciPy: `scipy.optimize.differential_evolution`

**Genetic Algorithms**
- Population-based; selection, crossover, mutation operators
- DEAP library (Python): flexible evolutionary computation framework

### Constrained Optimization and Linear Programming

FBA uses linear programming:
```
maximize: c·v
subject to: S·v = 0, v_min ≤ v ≤ v_max
```

- Simplex method: exact; moves along edges of feasible polytope
- Interior point: exact; moves through interior of polytope
- SciPy: `scipy.optimize.linprog`; but COBRApy uses `optlang` which wraps CPLEX/Gurobi/GLPK
- GLPK: open source; adequate for most GEMs
- CPLEX/Gurobi: commercial; 10–100× faster; required for ME-models

### Numba JIT Compilation

```python
from numba import jit, njit
import numpy as np

@njit  # no-Python mode: fastest; no Python objects
def gillespie_step(rates, populations):
    a0 = rates.sum()
    tau = -np.log(np.random.random()) / a0
    j = np.searchsorted(np.cumsum(rates), np.random.random() * a0)
    return tau, j
```

- `@jit`: tries nopython, falls back to object mode
- `@njit`: strict nopython; fails loudly if not possible
- First call is slow (compilation); subsequent calls are fast
- Speedup: typically 10–100× over pure Python loops

### Vectorization

```python
# Slow: Python loop over array
for i in range(len(x)):
    result[i] = x[i]**2 + 2*x[i] + 1

# Fast: NumPy vectorized
result = x**2 + 2*x + 1  # broadcasts over array; runs in C
```

Broadcasting rules:
- Arrays with compatible shapes operate element-wise
- Dimensions of size 1 broadcast to match larger dimension
- Avoid: loops over large arrays; list comprehensions for numerical work

### JAX for High-Performance Differentiable Programming

```python
import jax
import jax.numpy as jnp

@jax.jit  # compile to XLA for CPU/GPU/TPU
def ode_rhs(state, t, params):
    α, K, n, δ = params
    x = state
    return α * x**n / (K**n + x**n) - δ * x

# Automatic differentiation: gradient of loss w.r.t. parameters
loss_grad = jax.grad(compute_loss, argnums=0)  # gradient w.r.t. first arg
```

JAX use cases:
- Parameter estimation with gradient-based optimization
- Neural ODE training (ODE right-hand side parameterized by neural net)
- Monte Carlo inference requiring fast likelihood evaluations
