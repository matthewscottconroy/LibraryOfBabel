# 4.5 Software Engineering for Research

Building tools that work, can be understood, and can be used by others.

## Reproducibility as a First-Class Concern

Scientific software has a reproducibility crisis:
- Papers cannot be reproduced because code/data are unavailable
- Code runs on the author's machine but not others (dependency hell)
- Analysis steps not documented; cannot reconstruct from methods section
- Raw data lost; only summary statistics remain

Every tool you build should be reproducible by a stranger with no context. Build for that person from day one.

## Model Exchange Formats

### SBML (Systems Biology Markup Language)

Standard XML format for biochemical models. Every published systems biology model should be deposited in SBML.

```xml
<sbml xmlns="http://www.sbml.org/sbml/level3" level="3" version="2">
  <model id="repressilator">
    <listOfCompartments>
      <compartment id="cell" size="1"/>
    </listOfCompartments>
    <listOfSpecies>
      <species id="m1" initialAmount="0" compartment="cell"/>
      <species id="p1" initialAmount="0" compartment="cell"/>
    </listOfSpecies>
    <listOfReactions>
      <reaction id="transcription_1">
        <kineticLaw>
          <math>alpha / (1 + pow(p3/K, n))</math>
        </kineticLaw>
      </reaction>
    </listOfReactions>
  </model>
</sbml>
```

**Libraries:**
- `libSBML` (C++/Python): read, write, validate SBML
- `python-libsbml`: Python wrapper
- `roadrunner`: SBML simulator (fastest)
- `tellurium`: Python environment for systems biology modeling using Antimony

### Antimony: Human-Readable Model Language

```python
import tellurium as te

model_str = """
var m1, m2, m3, p1, p2, p3;
J1: -> m1; alpha/(1 + p3^n) + alpha0 - delta*m1;
J2: -> m2; alpha/(1 + p1^n) + alpha0 - delta*m2;
J3: -> m3; alpha/(1 + p2^n) + alpha0 - delta*m3;
J4: -> p1; beta*(m1 - p1);
J5: -> p2; beta*(m2 - p2);
J6: -> p3; beta*(m3 - p3);

alpha = 100; alpha0 = 0.0001; n = 2; delta = 1; beta = 1;
m1 = 0.1; m2 = 0.2; m3 = 0.3;
"""

r = te.loadAntimonyModel(model_str)
result = r.simulate(0, 100, 1000)
r.plot()
```

Antimony is far more readable than raw SBML — write in Antimony, export to SBML for distribution.

### BioNetGen: Rule-Based Modeling

For combinatorial complexity (receptor signaling, molecular modifications):

```
# EGF-EGFR binding rule
EGFR(lig,Y1045~U,Y1086~U) + EGF(rec) <-> EGFR(lig!1,Y1045~U,Y1086~U).EGF(rec!1) kon,koff

# Phosphorylation rule (conditional on dimerization)
EGFR(lig!+,Y1045~U) -> EGFR(lig!+,Y1045~P) kphos
```

- Rules generate all possible species automatically
- Avoids combinatorial explosion in SBML (manually listing all complexes)
- BioNetGen → SBML export; BNGL simulator

## Workflow Management

### Snakemake

Best choice for bioinformatics pipelines:

```python
# Snakefile
configfile: "config.yaml"

SAMPLES = config["samples"]

rule all:
    input:
        expand("results/de/{sample}_de.csv", sample=SAMPLES),
        "results/multiqc/report.html"

rule trimming:
    input:
        r1 = "data/raw/{sample}_R1.fastq.gz",
        r2 = "data/raw/{sample}_R2.fastq.gz"
    output:
        r1 = "data/trimmed/{sample}_R1.fastq.gz",
        r2 = "data/trimmed/{sample}_R2.fastq.gz",
        json = "data/trimmed/{sample}_fastp.json"
    shell:
        "fastp -i {input.r1} -I {input.r2} -o {output.r1} -O {output.r2} "
        "--json {output.json} --thread 4"

rule alignment:
    input:
        r1 = rules.trimming.output.r1,
        r2 = rules.trimming.output.r2,
        genome = config["star_genome"]
    output:
        bam = "data/aligned/{sample}/Aligned.sortedByCoord.out.bam",
        log = "data/aligned/{sample}/Log.final.out"
    threads: 8
    shell:
        "STAR --runThreadN {threads} --genomeDir {input.genome} "
        "--readFilesIn {input.r1} {input.r2} --readFilesCommand zcat "
        "--outSAMtype BAM SortedByCoordinate "
        "--outFileNamePrefix data/aligned/{wildcards.sample}/"
```

**Key features:**
- DAG inference: automatically determines execution order
- Re-runs only necessary steps when inputs change
- Cluster submission: `snakemake --cluster "sbatch {params.slurm}"`
- Container support: `container: "docker://biocontainers/star:2.7.10a"`

### Nextflow

DSL2 syntax; better for production pipelines and containerization:

```nextflow
process FASTP {
    container 'biocontainers/fastp:0.23.2'
    
    input:
    tuple val(sample_id), path(reads)
    
    output:
    tuple val(sample_id), path("*.fastq.gz"), emit: reads
    path "*.json", emit: json
    
    script:
    """
    fastp -i ${reads[0]} -I ${reads[1]} \
          -o ${sample_id}_R1.fastq.gz -O ${sample_id}_R2.fastq.gz \
          --json ${sample_id}_fastp.json
    """
}
```

**Nextflow vs. Snakemake:**
- Nextflow: better for cloud (AWS Batch, Google Cloud); stronger containerization
- Snakemake: better for HPC SLURM; more Pythonic; easier to read

## Containerization

### Docker

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y \
    libhdf5-dev \
    && rm -rf /var/lib/apt/lists/*

# Install Python dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy source
COPY src/ ./src/

# Default command
CMD ["python", "src/simulate.py"]
```

Build and run:
```bash
docker build -t my-biosim:1.0 .
docker run --rm -v $(pwd)/data:/data my-biosim:1.0
```

**Multi-stage builds** (smaller images):
```dockerfile
# Build stage
FROM python:3.11 AS builder
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# Runtime stage
FROM python:3.11-slim
COPY --from=builder /root/.local /root/.local
COPY src/ ./src/
```

### Singularity/Apptainer (HPC)

Docker requires root; Singularity does not:
```bash
# Convert Docker image to Singularity
singularity pull docker://biocontainers/star:2.7.10a

# Run in SLURM job
singularity exec star_2.7.10a.sif STAR --runThreadN 8 ...
```

## Data Management

### Zenodo and Figshare

- Archive: raw data, processed data, models, code
- Zenodo: free, unlimited; GitHub integration (auto-archive releases)
- Figshare: similar; commercial backing; better visualization
- DOI assigned: citable; persistent

### Data Formats for Large Datasets

**HDF5 / h5py**
```python
import h5py
import numpy as np

# Write
with h5py.File('simulations.h5', 'w') as f:
    f.create_dataset('trajectories', data=trajectories, compression='gzip')
    f.attrs['model'] = 'repressilator'
    f.attrs['n_runs'] = 1000
    f.attrs['parameters'] = str(params)

# Read
with h5py.File('simulations.h5', 'r') as f:
    traj = f['trajectories'][:]
```

**Zarr (cloud-friendly)**
- Chunked arrays; native cloud storage (S3, GCS)
- Better than HDF5 for parallel access
- AnnData (scRNA-seq) can use Zarr backing

### Versioning Data with DVC

```bash
dvc init
dvc add data/raw/expression_matrix.h5
git add data/raw/expression_matrix.h5.dvc .dvc/
git commit -m "Add expression data tracking"
dvc push  # push to remote storage (S3, GCS, local)
```

DVC tracks data versions alongside code versions — reproduce any analysis exactly.

## Publication-Quality Figures

```python
import matplotlib.pyplot as plt
import matplotlib as mpl
import numpy as np

# Publication settings
mpl.rcParams.update({
    'font.family': 'Arial',
    'font.size': 8,
    'axes.linewidth': 0.8,
    'xtick.major.width': 0.8,
    'ytick.major.width': 0.8,
    'lines.linewidth': 1.2,
    'figure.dpi': 300,
})

fig, axes = plt.subplots(1, 2, figsize=(7, 3))

# Panel labels
for ax, label in zip(axes, ['A', 'B']):
    ax.text(-0.15, 1.02, label, transform=ax.transAxes,
            fontsize=10, fontweight='bold')

plt.tight_layout()
plt.savefig('figure1.pdf', bbox_inches='tight')  # PDF for submission
plt.savefig('figure1.png', dpi=300, bbox_inches='tight')  # PNG for web
```

**Figure checklist:**
- [ ] Axis labels with units
- [ ] Legend if multiple lines/colors
- [ ] Error bars with n stated in caption
- [ ] Colorblind-safe palette (ColorBrewer, viridis)
- [ ] Font size ≥ 6 pt in final print size
- [ ] Vector format (PDF/SVG) for line figures
