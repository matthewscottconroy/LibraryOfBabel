The bioinformatics stack for a modern RNA-seq analysis might include Python 3.11, R 4.3, fastp 0.23, STAR 2.7.11, featureCounts from the Subread package, samtools 1.19, and six Python packages each pinned to specific versions. Installing all of this correctly on a single machine is a multi-hour task requiring careful attention to dependency conflicts. Getting it installed identically on three different machines — your laptop, the lab server, and a collaborator's workstation — is an exercise in frustration. Getting it installed on an HPC cluster where you do not have root access, on a cloud VM that might be ephemeral, or in a state that remains functional five years from now, borders on impossible without the right tools.

Containers solve this problem. A container packages an entire software environment — operating system libraries, runtime, binaries, Python packages — into a single portable unit that runs identically wherever the container runtime is available. The environment is specified once, reproducibly, and then distributed as a versioned artifact that can be pulled and executed anywhere.

The first subsection covers Docker, the dominant container technology for development environments, local testing, and cloud computing. A Dockerfile is a recipe: a series of instructions that build up a software environment layer by layer from a base image. Once built, the image is uploaded to a registry and can be pulled by anyone with network access. Docker enables the pattern of developing an analysis locally, testing it in the container, and then running the exact same container in production — whether "production" is a cloud VM, a collaborator's machine, or a CI system running automated tests.

The second subsection covers Singularity/Apptainer, the container system designed specifically for high-performance computing. Docker requires a root-owned daemon, which is a security liability on shared HPC clusters — system administrators universally disable it. Apptainer solves this: containers run as the invoking user, require no daemon, and are distributed as single `.sif` files that can be moved like any other file. Crucially, Apptainer can pull Docker images directly from registries and convert them to `.sif` format, meaning the same container you built and tested locally with Docker runs on the HPC with Apptainer — no separate build step required.
