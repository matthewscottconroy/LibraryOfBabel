A 2016 survey of researchers across scientific disciplines found that more than 70% had tried and failed to reproduce another scientist's experiment. When those researchers were asked what made reproduction difficult, missing or inadequate data was consistently among the top responses. Not fraudulent data — simply data that was no longer accessible, no longer in a usable format, or no longer accompanied by enough documentation to understand what it represented. Research data has historically been treated as a byproduct of publications rather than as a scientific artifact in its own right. The result is a vast and growing body of published results whose underlying evidence is permanently inaccessible.

This section addresses data management from three distinct but complementary perspectives: archival and discoverability, format and scale, and versioning and provenance. Together, these three topics constitute what it actually means to manage data responsibly over the full lifecycle of a research project — from the first raw data file through publication and beyond.

The first subsection covers Zenodo and figshare, the two dominant platforms for research data archiving. The key abstraction is the DOI — a permanent, globally resolvable identifier assigned to every uploaded dataset, software release, or figure. DOIs decouple the citation from the storage location: if a publisher changes its file hosting, the DOI still resolves. If a lab's server goes offline when the PI retires, the DOI still resolves. The GitHub-Zenodo integration is particularly elegant: configuring your repository once means that every versioned GitHub release automatically receives a DOI, so your software is permanently citable without any manual deposition workflow.

The second subsection covers data formats for large datasets. At the scale of modern genomics — tens of thousands of genes, hundreds of thousands of cells, gigabytes per experiment — format choice is not a matter of preference but of feasibility. You will work through HDF5, the hierarchical binary format that has become the standard for structured scientific data, and Zarr, its cloud-native counterpart optimized for parallel I/O. The AnnData format, which wraps HDF5 with scanpy-compatible structure, is the current standard for single-cell data.

The third subsection covers DVC — Data Version Control — a Git extension that extends version control to large binary files and analysis pipelines. DVC solves the question "which version of the data produced these figures?" by tracking data file checksums alongside code in Git, so that any historical analysis can be exactly reconstructed with `git checkout` followed by `dvc checkout`. The pipeline tracking features go further, combining dependency management with data versioning into a single provenance record for the entire analysis.
