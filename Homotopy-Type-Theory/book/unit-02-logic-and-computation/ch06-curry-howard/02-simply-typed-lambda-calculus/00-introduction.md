Church's untyped lambda calculus is computationally universal but logically useless. The problem is self-application: $\lambda x.\, x\, x$ is a perfectly good untyped term, and applying it to itself produces an infinite loop — a proof, under Curry-Howard, of anything you like. A system where every proposition is provable is not a logic; it is a collapse. Types are the fix. By requiring every lambda abstraction to carry an explicit domain type and prohibiting the formation of terms that would loop forever, the simply typed lambda calculus converts an undisciplined computation model into a genuine logic-programming isomorphism.

The STLC is austere: types are built from base types and function types only, terms are variables, lambda abstractions with annotated domains, and applications. But this austerity is not poverty. Under Curry-Howard, STLC is exactly intuitionistic propositional logic. A type $A \to B$ is the proposition "if $A$ then $B$," and a term of that type is a function converting proofs of $A$ to proofs of $B$. Adding product types gives conjunction; adding sum types gives disjunction; the empty type is $\bot$; the unit type is $\top$. The full propositional logic appears as a type theory with four constructs.

What you should notice — and what becomes central in the following sections — is that STLC's termination is a theorem requiring proof, not a design feature. The proof uses logical relations: a semantic method that defines a reducibility predicate by induction on types, not on terms. This technique is not just for STLC. Logical relations are the standard tool for proving strong normalization in every more powerful type theory, including System F and the calculus of constructions. Learning the technique here, where it is clearest, prepares you for its appearances in increasingly powerful settings.
