# Simply Typed Lambda Calculus

## The Problem with Untyped Lambda Calculus

Church's untyped lambda calculus, introduced in the 1930s, is a formal system for computation. Its three constructs — variables $x$, lambda abstractions $\lambda x.\, t$, and applications $t\, s$ — can define any computable function. The untyped lambda calculus is Turing-complete.

But Turing-completeness is a double-edged sword. The untyped lambda calculus allows self-application: the term $\omega = \lambda x.\, x\, x$ applies $x$ to itself. Applied to itself: $\omega\, \omega = (\lambda x.\, x\, x)(\lambda x.\, x\, x) \to (\lambda x.\, x\, x)(\lambda x.\, x\, x) = \omega\, \omega$. This term reduces to itself — an infinite loop. It never produces a value.

From the logical perspective, this is catastrophic. Under Curry-Howard, terms are proofs. A non-terminating proof is a proof of $\bot$ — an inconsistency. If every type is inhabited (if we can write a term of any type by looping forever), then every proposition is provable and the logic is trivial.

Types fix this. The simply typed lambda calculus (STLC) adds a type discipline that rules out self-application, guarantees termination, and makes the Curry-Howard correspondence into a genuine logic-programming isomorphism.

## Syntax of STLC

**Types** are generated by:
$$A, B, C ::= \alpha \mid A \to B$$

where $\alpha$ ranges over *base types* (atomic types like $\mathsf{Nat}$, $\mathsf{Bool}$, $\mathsf{Prop}$) and $A \to B$ is the *function type*. We can add product types $A \times B$, sum types $A + B$, the empty type $\mathbf{0}$, and the unit type $\mathbf{1}$ as primitives or definitions.

**Terms** are generated by:
$$t, s ::= x \mid \lambda x : A.\, t \mid t\, s$$

- **Variable** $x$: a name, typed by context.
- **Lambda abstraction** $\lambda x : A.\, t$: a function binding variable $x$ of type $A$ in body $t$. The annotation $: A$ is optional in Church-style (explicit types) and inferred in Curry-style.
- **Application** $t\, s$: apply function $t$ to argument $s$.

**Typing contexts** $\Gamma$ are finite lists of variable-type pairs: $\Gamma = x_1 : A_1, \ldots, x_n : A_n$.

## Typing Rules

The three core typing rules:

**Variable**:
$$\frac{}{\Gamma, x : A \vdash x : A} \quad (\text{Var})$$
A variable has the type declared in the context.

**Lambda Abstraction**:
$$\frac{\Gamma, x : A \vdash t : B}{\Gamma \vdash \lambda x : A.\, t : A \to B} \quad (\text{Abs})$$
If, assuming $x$ has type $A$, the body $t$ has type $B$, then the lambda abstraction has type $A \to B$.

**Application**:
$$\frac{\Gamma \vdash f : A \to B \quad \Gamma \vdash a : A}{\Gamma \vdash f\, a : B} \quad (\text{App})$$
Applying a function of type $A \to B$ to an argument of type $A$ gives a result of type $B$.

For product types, add:

**Pairing**:
$$\frac{\Gamma \vdash a : A \quad \Gamma \vdash b : B}{\Gamma \vdash (a, b) : A \times B}$$

**Projections**:
$$\frac{\Gamma \vdash p : A \times B}{\Gamma \vdash \pi_1\, p : A} \qquad \frac{\Gamma \vdash p : A \times B}{\Gamma \vdash \pi_2\, p : B}$$

These rules, as discussed in the previous section, are isomorphic to the natural deduction rules for $\to$ and $\wedge$ under the Curry-Howard correspondence.

## Reduction Rules

**Beta reduction**:
$$(\lambda x : A.\, t)\, a \to_\beta t[a/x]$$
Applying a lambda abstraction to an argument substitutes the argument for the bound variable. This is the fundamental computation step.

**Eta reduction**:
$$\lambda x.\, f\, x \to_\eta f \quad (\text{when } x \notin \text{FV}(f))$$
A function that takes an argument and applies $f$ to it is extensionally equal to $f$.

**Product reductions**:
$$\pi_1((a, b)) \to_\beta a \qquad \pi_2((a, b)) \to_\beta b$$

A term is in **normal form** if no reductions apply. The normalization theorem (proven in Section 3) says every well-typed STLC term reduces to a unique normal form.

## Church-Style vs. Curry-Style

There are two conventions for type annotations in lambda calculus:

**Church-style** (intrinsic types): every term has exactly one type. Type annotations are part of the term: $\lambda x : A.\, t$ explicitly records the type of the bound variable. Type checking is decidable (just read off the annotations) but terms can only be used at their declared type.

**Curry-style** (extrinsic types): types are assigned to terms by an external judgment. The same untyped term $\lambda x.\, x$ can have type $A \to A$ for any $A$ (it is the identity function). Type checking requires unification. This is the basis of ML/Haskell's type inference: the term $\lambda x.\, x$ has the principal type $\forall \alpha.\, \alpha \to \alpha$ (in the Hindley-Milner system).

Church-style is more natural for dependent type theory (types can depend on terms, so annotations must be explicit). Curry-style is more natural for practical programming (less annotation overhead). Proof assistants like Agda and Coq use Church-style; Haskell and ML use Curry-style with elaboration.

## Derivation-as-Term Correspondence

Every derivation tree in STLC corresponds to a term, and every well-typed term corresponds to a derivation tree. This is the formal content of Curry-Howard.

Consider the derivation of $\vdash \lambda f.\, \lambda x.\, f\, x : (A \to B) \to A \to B$:

$$\frac{
  \frac{
    \frac{}{f : A \to B, x : A \vdash f : A \to B} \quad \frac{}{f : A \to B, x : A \vdash x : A}
  }{f : A \to B, x : A \vdash f\, x : B}
}{f : A \to B \vdash \lambda x : A.\, f\, x : A \to B} \to \frac{}{\vdash \lambda f.\, \lambda x.\, f\, x : (A \to B) \to A \to B}$$

This term is the "apply" function — given $f$ and $x$, apply $f$ to $x$. It is the proof of $(A \to B) \to A \to B$ in natural deduction: from a proof that $A$ implies $B$ and a proof of $A$, derive $B$.

Every natural deduction proof of $\Gamma \vdash A$ corresponds to a unique (up to alpha-equivalence) STLC term $t$ with $\Gamma \vdash t : A$. And conversely.

## The Substitution Lemma

The central metatheorem about STLC, used in virtually every proof about the system:

**Lemma (Substitution Preserves Typing).** If $\Gamma, x : A \vdash t : B$ and $\Gamma \vdash s : A$, then $\Gamma \vdash t[s/x] : B$.

*Proof.* By induction on the derivation of $\Gamma, x : A \vdash t : B$.

- If $t = x$: then $t[s/x] = s$, and $\Gamma \vdash s : A = B$ (since $t = x$ forces $A = B$).
- If $t = y$ for $y \neq x$: then $t[s/x] = y$, and $y : B$ is in $\Gamma$.
- If $t = \lambda y : C.\, u$: then $t[s/x] = \lambda y : C.\, u[s/x]$, and by induction hypothesis on $u$. $\square$

The substitution lemma says: substituting a well-typed term for a well-typed variable produces a well-typed result. This is the type-theoretic content of "using a hypothesis": if we have a proof of $A$ and a derivation that uses $A$ as a hypothesis, substituting the proof for the hypothesis gives a valid derivation.

## Preservation and Progress

**Theorem (Preservation / Subject Reduction).** If $\Gamma \vdash t : A$ and $t \to_\beta t'$, then $\Gamma \vdash t' : A$.

Types are preserved by computation. If a term has type $A$, and we perform a beta reduction, the result still has type $A$. This is proved by induction on the reduction step, using the substitution lemma for the beta case.

**Theorem (Progress).** If $\vdash t : A$ (closed term with no free variables), then either:
- $t$ is a *value* (in normal form: a lambda abstraction, a pair, or an element of a base type), or
- $t \to_\beta t'$ for some $t'$.

Progress says well-typed programs are not "stuck": they either have already computed a value, or they can make progress. This rules out "type errors at runtime" — the standard formulation of type safety.

Together, preservation and progress give type safety: a well-typed closed term either evaluates to a value or continues reducing, and all intermediate terms are well-typed of the same type.

## Examples: Familiar Programs as Proofs

**Identity**: $\vdash \lambda x : A.\, x : A \to A$. Proof of $A \to A$: assume $A$, return $A$.

**Composition**: $\vdash \lambda f.\, \lambda g.\, \lambda x.\, g\, (f\, x) : (A \to B) \to (B \to C) \to (A \to C)$. Proof of $(A \to B) \to (B \to C) \to (A \to C)$: given functions and an input, compose them.

**Swap**: $\vdash \lambda p.\, (\pi_2\, p, \pi_1\, p) : A \times B \to B \times A$. Proof of $A \wedge B \to B \wedge A$.

**Curry**: $\vdash \lambda f.\, \lambda x.\, \lambda y.\, f\, (x, y) : (A \times B \to C) \to A \to B \to C$. Proof of $(A \wedge B \to C) \to A \to B \to C$.

**Uncurry**: $\vdash \lambda f.\, \lambda p.\, f\, (\pi_1\, p)\, (\pi_2\, p) : (A \to B \to C) \to A \times B \to C$. Proof of $(A \to B \to C) \to A \wedge B \to C$.

These programs are simultaneously implementations of standard functional programming utilities and proofs of logical tautologies. The Curry-Howard correspondence makes this concrete.
