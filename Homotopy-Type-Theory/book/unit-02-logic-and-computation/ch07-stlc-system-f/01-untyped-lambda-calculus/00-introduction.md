Church's lambda calculus begins with a single radical hypothesis: everything is a function. There are no numbers, no booleans, no data structures as primitives — only lambda abstractions and application. What makes this more than a curiosity is that it is enough. Every computable function can be represented; Turing-completeness is provable. The poverty of the language is its strength: its mathematical tractability comes from having almost nothing to work with, and almost nothing turns out to be everything.

The encoding of data as functions — Church numerals, Church booleans, Church pairs — reveals the principle that governs inductive types throughout all of type theory. A natural number is something that can iterate a function $n$ times. A boolean is something that can choose between two values. A list is something that can fold over its elements. Data is represented by what it *does* when used in case analysis, not by how it looks inside. This principle — that the eliminator characterizes the type — reappears in MLTT as the recursion principle, in HoTT as the induction principle, and in Lean as the `rec` declaration.

There is a price. The untyped lambda calculus is logically trivial: the self-application term $\omega = \lambda x.\, x\, x$, applied to itself, diverges forever. Under Curry-Howard, divergence is a proof of anything, so the untyped system proves every proposition. This is not a logic; it is a computation model that must be disciplined before it can reason. Types are that discipline. The next sections show how adding types removes the diverging terms while preserving the computational power needed for expressing logic — and why the restrictions that enforce termination are exactly the restrictions that enforce consistency.
