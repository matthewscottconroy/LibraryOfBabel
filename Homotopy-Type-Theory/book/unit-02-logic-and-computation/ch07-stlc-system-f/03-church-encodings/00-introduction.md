Church encodings perform an act that seems impossible: they represent all data types — booleans, natural numbers, lists, trees — as pure functions, inside a language that has no built-in data structures at all. The trick is a principle that becomes foundational throughout type theory: *a datum is represented by its eliminator*. A boolean is a function that, given two options, selects one. A natural number is a function that, given a base case and a step function, iterates the step $n$ times. The data is not stored; it is embodied in a behavior.

The non-obvious consequence is that in System F — the polymorphic lambda calculus — Church encodings give these types genuinely polymorphic types. Church-encoded $\mathsf{Nat}$ has type $\forall \alpha. (\alpha \to \alpha) \to \alpha \to \alpha$, which says precisely "for any type $\alpha$, given a step function and a base, iterate." The encoding reveals that induction — the principle that makes natural number reasoning work — is a polymorphic function, not a special-purpose axiom. This is the connection between Church encodings and the recursion principles of MLTT.

The limitation of Church encodings is also instructive. In STLC, Church-encoded natural numbers cannot support primitive recursion without type-level machinery — you cannot define predecessor in constant space. In System F, this limitation is removed, but at the cost of impredicativity: the universal quantifier ranges over all types, including the type being defined. In MLTT and HoTT, inductive types are added as first-class primitives with their own formation, introduction, and elimination rules precisely because the encoding approach has known deficiencies. Understanding what Church encodings achieve, and where they fall short, explains why modern type theories include inductive types as primitives rather than encoding them away.
