The move from simple types to dependent types begins with a single idea that sounds almost trivial: a type can be indexed by a value. Not by another type — polymorphism already gives you that — but by an actual term, a specific value that exists at runtime. The result is a *type family*, a function B : A → Type that produces a different type for each element of A. Allow this, and everything changes.

What makes type families surprising is how much mathematical content they absorb. The gap between a list and a list of length exactly five, between a function and an injective function, between a natural number and a prime — these are distinctions that simple type theory cannot see. Type families can see all of them. Vec : ℕ → Type maps each number to the type of vectors of that length; Fin : ℕ → Type maps each number to a finite type with exactly that many elements. In both cases, properties that would previously require runtime checks or separate verification become enforced by the type system at compile time.

This section develops type families as the foundational concept underlying everything in dependent type theory. The formal judgment that B is a type family over A is the first step toward both Π types and Σ types — the two great constructions built from a type and a type family over it. More distantly, it is the step toward equality as a type: the identity type a =_A b is itself a type family over A × A, and its elements — proofs of equality — are what HoTT will later treat as paths in a space. The whole edifice rests here.
