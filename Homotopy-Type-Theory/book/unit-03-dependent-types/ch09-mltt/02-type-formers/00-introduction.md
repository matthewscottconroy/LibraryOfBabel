Once you have seen how Π types and Σ types work, a pattern becomes visible. Every type in MLTT is introduced by the same four-step ritual: a formation rule that says when the type is well-formed, an introduction rule that says how to build elements, an elimination rule that says how to use elements, and a computation rule that says what the elimination produces on canonical inputs. This is the FIEC pattern — Formation, Introduction, Elimination, Computation — and it is the universal grammar of type-theoretic definitions.

What is non-obvious is that the FIEC pattern is not a stylistic convention. It is a deep constraint on what a type former is allowed to be. The introduction rules determine the eliminator uniquely: once you commit to the constructors, the induction principle is forced. The computation rules then say that applying the eliminator to something built by the introduction rules reduces to the case you specified. This is the same principle underlying inductive types — constructors and eliminators are dual — generalized to the entire system. In practice, this means you can understand any new type former in MLTT by asking four questions: what do I need to form it, how do I build elements, how do I use elements, and what does use-after-build reduce to.

This section collects the full FIEC rules for every standard type former in MLTT: Π, Σ, identity, the empty type, the unit type, booleans, natural numbers, and universes. Reading this collection as a whole, rather than type-by-type, reveals the structural uniformity of the system. It also shows where the identity type is anomalous — its elimination rule (J) is more subtle than projection or application, and understanding why prepares you for path induction and everything that follows in HoTT.
