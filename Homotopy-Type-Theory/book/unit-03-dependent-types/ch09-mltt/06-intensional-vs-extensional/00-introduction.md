Martin-Löf published two distinct versions of his type theory, and they differ by exactly one rule. That rule — the reflection rule, which promotes a propositional equality proof into a definitional equality — changes the character of the entire system. The two versions agree on what is provable in many cases, but they disagree profoundly on what type-checking means, what the identity type can express, and whether HoTT is possible at all.

In intensional MLTT, definitional equality (≡) and propositional equality (=) are kept strictly separate. The type checker decides ≡ automatically by normalization; proving = requires constructing a term. This separation has a decisive practical consequence: type-checking is decidable. The normalization algorithm terminates and produces unique normal forms, so verifying any typing judgment is a finite mechanical process. It is also the feature that makes HoTT possible: because = is not automatically ≡, the identity type can have multiple distinct inhabitants, and there is room for non-trivial paths. In extensional MLTT, the reflection rule collapses the distinction: any proof p : a = b entitles the type checker to accept a ≡ b. The immediate gain is convenience — you never need to explicitly transport along equality proofs. The cost is that type-checking becomes undecidable, because checking ≡ can now require deciding arbitrary propositional equalities.

The choice between these two versions is not merely technical. It determines what kind of mathematics you can express and what you can automate. Extensional MLTT is closer to ordinary mathematical practice, where equal things are freely substituted, but it makes proof checking fundamentally non-algorithmic. Intensional MLTT forces you to be explicit about transport and path structure, but it gives you a decidable type checker and, through HoTT, a model of types as spaces where equality has genuine geometric content. Every proof assistant you work with has made this choice, and the choice shapes everything about how you prove theorems in it.
