Equality in simple type theory behaves cleanly: if two elements are equal, a function maps them to equal outputs. Leibniz's law. One line. In dependent type theory, the same intuition applies but the mechanics become genuinely interesting. If a and b are equal elements of A, then any property P that holds of a ought to hold of b as well. But P(a) and P(b) are, in general, different types — and an element of one is not automatically an element of the other. To move between them, you need the equality proof itself as a guide.

Transport is the operation that does this moving. A path p from a to b in A lifts to a function from P(a) to P(b) for any type family P over A, and this function is an equivalence — its inverse is transport along the reverse path. The geometric intuition is clear: a path in the base lifts to a transport of the fiber, and going back undoes the transport. This is the language of fiber bundles, internalized into type theory as a theorem about identity types.

The companion operation, ap, handles the non-dependent case: a function f from A to B sends a path in A to a path in B by composition. Together, transport and ap are how paths propagate through the structure of a type theory. Every theorem about equality that involves functions — every computation, every substitution, every coherence proof — uses these two operations, often without naming them. Understanding transport and ap clearly is not optional. They are the infrastructure on which everything in HoTT is built.
