# Truncations as Higher Inductive Types

## From Promises to Definitions

In Chapter 17, we introduced truncations — the operations that force a type to a given h-level — and stated their universal properties. We promised they existed, giving the universal properties as characterizations. Now we deliver: truncations are HITs, with explicit path (and higher path) constructors that force the h-level.

This is important for two reasons. First, it gives an existence proof: truncations are not merely postulated — they are constructed, within the type theory, as HITs. Second, it clarifies the computational content: the path constructors of a truncation HIT are the precise witnesses of the h-level collapse.

## Propositional Truncation as a HIT

**Definition.** The propositional truncation ‖A‖ is the HIT with:
- Constructor: `|a| : ‖A‖` for each a : A
- Path constructor: `squash(x, y) : x = y` for all x, y : ‖A‖

The squash path constructor forces ‖A‖ to be a proposition: any two elements are equal.

**Eliminator.** To define f : ‖A‖ → B where B is a proposition:
- `f(|a|) = g(a)` for some g : A → B
- The squash condition is automatically satisfied: since B is a proposition, f(x) = f(y) for any x, y : ‖A‖ (both are in B, which is a proposition).

If B is not a proposition, we cannot eliminate from ‖A‖ into B — doing so would extract the specific element of A, which the truncation is designed to forget.

**Universal property.** For any proposition P:
```
(‖A‖ → P)  ≃  (A → P)
```

**Why squash has the type it does.** The squash path constructor has type `Π(x y : ‖A‖). x = y` — a path constructor for all pairs of elements. This is different from an ordinary path constructor like `loop : base = base` in S^1, which specifies a single path. The universally quantified path constructor `squash` forces every pair of elements to be equal, making ‖A‖ a proposition.

## Set Truncation as a HIT

**Definition.** The set truncation ‖A‖₀ is the HIT with:
- Constructor: `|a|₀ : ‖A‖₀` for each a : A
- Path-of-path constructor: `squash₀(x y : ‖A‖₀)(p q : x = y) : p = q`

The `squash₀` constructor forces all path types to be propositions — making ‖A‖₀ a set.

**Universal property.** For any set S:
```
(‖A‖₀ → S)  ≃  (A → S)
```

The set truncation is the "free set" generated by A — the set of connected components of A.

## General n-Truncation

The n-truncation ‖A‖_n is the HIT with:
- Constructor: `|a|_n : ‖A‖_n` for each a : A
- For each level m > n: path constructors that force all (m+1)-fold iterated path types to be contractible

More precisely, `‖A‖_n` has path constructors at level n+1 that force all (n+2)-fold path types to be contractible. The recursive definition:

- ‖A‖_{-1} = propositional truncation (squash path constructor)
- ‖A‖₀ = set truncation (squash on paths)
- ‖A‖_{n+1} = truncation with squash at level n+2

**Recursive truncation.** There is a natural equivalence:
```
‖A‖_n ≃ ‖‖A‖_{n-1}‖_n
```

You can truncate in stages: first truncate to level n-1, then to level n.

More usefully: ‖A‖_n ≃ ‖‖A‖_{n+1}‖_n (truncating down in one step versus two steps gives the same result).

## The Postnikov Tower via HITs

The n-truncation ‖A‖_n gives the n-th layer of the Postnikov tower:

```
A → ... → ‖A‖_2 → ‖A‖_1 → ‖A‖_0 → ‖A‖_{-1} → ‖A‖_{-2} = 1
```

Each map is a "truncation map" that discards homotopy information above level n.

The Postnikov tower decomposes A into its homotopy groups: the fiber of `‖A‖_n → ‖A‖_{n-1}` is a "K(πₙ(A), n)-bundle" — it captures the n-dimensional homotopy group information.

**Completeness.** The Postnikov tower "converges to A" in the sense that:
```
A ≃ lim_{n→∞} ‖A‖_n
```

(as a homotopy limit). A type is determined by its Postnikov tower plus the "k-invariants" specifying how the layers attach. This is the type-theoretic version of the classical Postnikov system.

## Truncation and Logic

The relationship between truncations and logic is:

| Truncation | Logical meaning | Type |
|---|---|---|
| ‖A‖ | A is merely inhabited (∃ without witness) | Proposition |
| ‖A‖₀ | Connected components of A | Set |
| A itself (no truncation) | A with full proof content | Type |

The difference between `Σ(x:A).P(x)` and `‖Σ(x:A).P(x)‖` is the difference between "there exists x in A with P(x), and I can give you such an x" versus "there merely exists x in A with P(x), and I may not be able to give you a specific one."

**The constructive spirit.** In constructive mathematics, "there exists" usually means "we can exhibit." The propositional truncation lets us state the *classical* "there exists" — mere inhabitation — within a constructive framework. We can then choose to work constructively (with Σ-types) or classically (with ‖Σ‖-types) depending on the mathematical situation.

## Truncation and the Axiom of Choice

The interaction between truncation and the axiom of choice is subtle and important.

**Type-theoretic choice (provable).** If for each a : A there is a specific element b : B(a) with P(a,b), then there is a function f : Π(a:A).B(a) with Π(a:A).P(a,f(a)).

This is provable: given the function a ↦ (b(a), p(a)), just project.

**Propositional choice (not provable in general).** If for each a : A there *merely* exists b : B(a) with P(a,b) (i.e., Π(a:A).‖Σ(b:B(a)).P(a,b)‖), can we find a function Π(a:A).B(a)?

This is not provable — it requires the Axiom of Choice. The truncation ‖−‖ prevents extracting the specific witness.

**When choice is automatic.** If each B(a) is *contractible* (not just inhabited), then we can always choose: take the center of contraction. Contractibility provides an automatic "choice function."

This explains the definition of equivalences via contractible fibers: the contractibility gives us automatic choice of a preimage for each element of the codomain.

## Summary

| HIT | Constructors | h-Level achieved | Universal property |
|---|---|---|---|
| ‖A‖ | |a|, squash | Proposition (-1) | (‖A‖ → P) ≃ (A → P) for P:Prop |
| ‖A‖₀ | |a|₀, squash₀ | Set (0) | (‖A‖₀ → S) ≃ (A → S) for S:Set |
| ‖A‖_n | |a|_n, squash_n | n-type | (‖A‖_n → B) ≃ (A → B) for B:n-type |

Truncations as HITs show that the h-level hierarchy is not just a classification scheme — it is actively constructible within type theory. The path (and higher path) constructors of a truncation HIT are the precise mechanisms by which homotopy information is collapsed. This makes the h-level hierarchy computable, not just descriptive.
