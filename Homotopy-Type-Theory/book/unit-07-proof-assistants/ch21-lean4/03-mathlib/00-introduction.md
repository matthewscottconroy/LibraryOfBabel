The Feit-Thompson theorem — that every finite group of odd order is solvable — took fifteen years and 150,000 lines of Coq to formalize. That was a landmark, but it was also a demonstration of how brutally expensive formalization at scale could be: one theorem, one team, one decade and a half. Mathlib changed the equation. By building a library that mathematicians could actually use and extend, it created the flywheel effect that single-theorem projects could not: each formalized result becomes a lemma for the next, each new contributor builds on the accumulated work of those before, and the library compounds. By 2025, Mathlib4 contains over 150,000 theorems — graduate-level real analysis, algebraic geometry, category theory, number theory — and it grows by hundreds per week.

Using Mathlib well is a skill distinct from knowing Lean 4 syntax. The library is vast, and navigating it efficiently requires knowing which tools to reach for: `exact?` to search for closing lemmas, `apply?` to find applicable hypotheses, `simp?` to see what the simplifier actually uses, and Loogle for semantic search over the entire library. The vocabulary of Mathlib has conventions — naming schemes, typeclass hierarchies, bundled versus unbundled structures — and learning those conventions is what transforms Mathlib from an intimidating archive into a practical instrument.

This section teaches you to search, import, and compose. You will learn how Mathlib's typeclass hierarchy packages algebraic structures, how to find the lemma you need among 150,000 candidates, and how to write proofs that reuse library results instead of reproving them. The goal is fluency: not just knowing that Mathlib has something, but knowing how to find it and how to fit it into your proof.
