The move from vanilla Agda to Cubical Agda is a move from a system where identity is an axiom to a system where identity *computes*. In ordinary Agda — and in book HoTT — a path from `a` to `b` is a primitive notion: you can reason about paths, transport along them, compose them, but they do not reduce. In Cubical Agda, a path from `a` to `b` is a function `p : I → A` satisfying `p i0 = a` and `p i1 = b` *definitionally*. The interval `I` is a new primitive sort with two endpoints, and paths are just functions on it. This single decision — paths are functions — cascades into computational content everywhere the theory touches identity.

The consequences are immediate and structural. Transport becomes a computation, not an axiom: to transport along a path `p : A ≡ B` means to apply the function `p` at a point of the interval, and the result reduces. Univalence — the principle that equivalent types are identical — is no longer an axiom added to the theory but a theorem derivable from the `Glue` type constructor. You do not merely assert that equivalent types are equal; Cubical Agda *proves* it, and the resulting equality computes. This is the key distinction: in book HoTT, the univalence axiom blocks computation; in Cubical Agda, it enables it.

This section develops the core Cubical vocabulary in depth: the interval `I` and its operations, the `Path` type, `hcomp` (homogeneous composition) and `transp` (transport), the `Glue` type that packages equivalences into paths, and how these primitives combine to give a full proof of univalence. You are learning a new kind of type theory — one where the geometry of paths is not metaphor but mechanism.
