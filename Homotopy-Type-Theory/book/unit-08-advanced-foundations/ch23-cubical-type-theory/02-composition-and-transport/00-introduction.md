Paths as functions solve one problem and immediately create another. If a path $p : a =_A b$ is a function $\mathbb{I} \to A$, then concatenating $p$ with $q : b =_A c$ cannot be done by simple function-level surgery — the interval has no total order to bisect, no midpoint to glue on. You have two functions on the same interval with a matching endpoint, but no primitive operation that stitches them into a single function. The ordinary mathematician's trick of parameterizing by $[0, 1/2]$ and $[1/2, 1]$ is simply not available.

The resolution is `hcomp`: the operation that fills open boxes. An open box is a partial cube — a square, say, with its bottom, left, and right faces specified but its top missing. The composition operation takes this partial data and produces the missing face. Path concatenation is the special case where the box is 2-dimensional and the missing face is the composite path. But `hcomp` is more than a concatenation trick; it is the Kan filling condition, the computational encoding of the fact that the types in cubical type theory are fibrant. Every type can fill every open box, and that uniformity is what makes them homotopy types.

Transport — moving an element of $A(a)$ to $A(b)$ along a path in the base — turns out to be equally fundamental, and equally non-trivial once types become functions. The `transp` operation handles this, and together `hcomp` and `transp` generate `comp`, the heterogeneous composition that fills boxes where the type itself varies across the interval. These three operations are the computational engine of cubical type theory. Everything downstream — the Glue type, the proof of univalence, the implementation of HITs — depends on filling boxes correctly and uniformly across all type formers.
