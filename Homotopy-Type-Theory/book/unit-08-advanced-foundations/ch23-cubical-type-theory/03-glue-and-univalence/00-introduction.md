Univalence changes status in cubical type theory. In book HoTT it is an axiom — a true principle that has no computational content, a judgment that halts reduction whenever a proof depends on it. The question the HoTT book leaves open is whether univalence could ever be a theorem rather than a postulate; whether the type theory could be extended so that `ua(e)` actually reduces. The Glue type is the answer.

The problem is composition in the universe. To prove univalence, you need a path in `Type` between any two equivalent types. A path in `Type` is a function $\mathbb{I} \to \mathsf{Type}$ — a family of types varying over the interval. Transporting along such a path is transport across a type family, which requires filling boxes in the universe. But filling a box in the universe means specifying, for each face of the box, a partial type and showing they assemble. The naive solution — take some colimit — fails because it has no computation rule; you would have a formal element with no reduction behavior. The Glue type instead introduces a concrete type former that records exactly the data needed: a base type $B$, a face specification $\phi$, a partial type $T$ over $\phi$, and an equivalence $e : T \simeq B$ witnessing the gluing. From this data, `glue` constructs elements and `unglue` extracts them, and both operations satisfy explicit reduction rules.

With Glue in hand, composition in the universe is Glue formation. The proof of univalence becomes a derivation: you exhibit the path in `Type` as a Glue type, verify the computation rules, and univalence falls out as a theorem. You are no longer postulating that equivalences are paths — you are computing them.
