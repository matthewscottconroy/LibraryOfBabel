CCHM is not the endpoint. The cubical type theory you have seen so far — interval with De Morgan algebra, `hcomp`, Glue types, univalence as a theorem — is one consistent and well-implemented system. But it sits inside a larger design space, and understanding the space reveals which features of cubical type theory are essential and which are contingent choices made for particular reasons.

The most significant fork is the complement operation. CCHM keeps $\sim$, the De Morgan involution on $\mathbb{I}$, because it gives path reversal definitionally and makes many cubical arguments dramatically simpler. Cartesian cubical type theory (CCTT) removes it. Without complement, path reversal is no longer a syntactic substitution; it requires a composition argument and becomes propositional rather than definitional. `sym (sym p) = p` is a theorem, not a reduction. This sounds like a loss — and in some sense it is — but the gain is a cleaner categorical metatheory: the Cartesian cube category is better understood, and canonicity and normalization proofs become more tractable. The implementation `cooltt` targets CCTT for exactly this reason.

A second axis concerns how strictly boundary conditions are enforced. XTT, two-level type theory (2LTT), and related systems make different choices about which equalities are definitional, how much of the cubical structure is strict versus propositional, and whether fibrant and non-fibrant types are separated. These choices have practical consequences for proof assistants: definitional equalities discharge proof obligations automatically but can make type-checking undecidable; propositional equalities are always checkable but require explicit witnesses. Surveying these variations is not idle taxonomy — it tells you which system to use for which purpose, and it clarifies the logical commitments built into each.
