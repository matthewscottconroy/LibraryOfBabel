# Chapter 23: Cubical Type Theory

## The Univalence Axiom Made It Beautiful. It Also Made It Stuck.

The Univalence Axiom made HoTT beautiful. It also made it stuck. Beautiful in that it captured the right notion of equality — equivalent types are equal, full stop, no qualification needed. Stuck in that the axiom had no computational content. When you compute with a path `ua(e)`, the computation simply stops. The axiom provides no reduction rule. The type checker sees `ua(e)` and doesn't know what to do with it. This is not acceptable for a system that claims computation and proof are the same thing.

This gap — the canonicity problem — was known from the beginning. The HoTT Book names it explicitly. A closed term of type ℕ should reduce to a numeral. In Book HoTT, it doesn't always. A term that uses `ua` in its derivation might produce something like `transport (ua succ-equiv) 3` and just stop there, a formal expression with no numerical value. The program doesn't run. The proof has no computational content.

The CCHM team — Cyril Cohen, Thierry Coquand, Simon Huber, Anders Mörtberg — solved this in 2016 by discovering a way to bake the interval into the type theory itself. The result: Univalence is not an axiom. It is a theorem. And it computes.

---

### The Key Move

The key move is deceptively simple to state: instead of treating paths as an inductive type generated by reflexivity, you treat them as *functions from an interval*. A path from $a$ to $b$ in type $A$ is literally a function $p : \mathbb{I} \to A$ with $p(0) = a$ and $p(1) = b$ — definitionally, not propositionally. Not "there exists a proof that $p(0)$ equals $a$" but "$p(0)$ *is* $a$" in the computational sense.

This changes everything downstream. Path reversal is now `λ i → p (~ i)` — you just negate the interval variable, using a complement operation that makes the interval a De Morgan algebra. Path concatenation uses a composition operation `hcomp` that fills open boxes in any type. Transport becomes `transp`, a primitive that computes how to move elements through a changing type family.

And then the crucial piece: the Glue type. A type former that encodes, at the level of syntax, what it means to stitch two types together along an equivalence. From the Glue type, `ua` is defined — not postulated. And its computation rule follows from the rules for Glue. `transport (ua e) a` reduces to `e a`. The computation runs.

---

### What Cubical Agda Is

Cubical Agda (`agda --cubical`) is the primary implementation of this theory. It is not a toy or a prototype. As of 2024, the Cubical Agda library contains:

- Complete proofs of the Seifert-van Kampen theorem
- The Blakers-Massey connectivity theorem
- The first synthetic proof of the Brunerie number ($\pi_4(S^3) = \mathbb{Z}/2\mathbb{Z}$), computed to a specific integer by the type checker
- Spectral sequences in cohomology
- The Eilenberg-MacLane spaces $K(G, n)$ for arbitrary groups $G$

The Brunerie number computation is worth pausing on. Guillaume Brunerie defined a term of type ℤ whose value should be $\pm 2$ (the order of $\pi_4(S^3) = \mathbb{Z}/2$). In Book HoTT, this term is stuck — it involves `ua` and cannot be computed. In Cubical Agda, it runs. The type checker evaluates it. It takes a few seconds. It returns $-2$. This is the canonicity theorem in action: computable univalence, not just formal univalence.

**Section 1: The Interval and Paths** — The CCHM interval $\mathbb{I}$ as a primitive with De Morgan algebra structure. Paths as functions $\mathbb{I} \to A$ with definitional endpoints. Face formulas, partial elements, extension types. Why the interval structure is the key that unlocks everything.

**Section 4: Variations** — Cartesian cubical type theory (no De Morgan structure, implemented in cooltt). XTT (boundary separation, strict equalities). 2-level type theory. What normalization and canonicity mean for proof assistants.
