# 1.1 The Interval Type and the Circle

## From Discrete to Continuous: The Idea

Ordinary inductive types are "discrete" — they have no interesting paths between distinct elements. The natural numbers are just a set of isolated points; $0 \neq 1$, and there's no path from $0$ to $1$.

Higher inductive types break this. The key idea: we can *declare* that certain paths exist, just as we declare that certain points exist.

For ordinary inductive types, the constructors say:
- "Here are the elements of this type"

For HITs, the constructors say:
- "Here are the elements of this type" (point constructors)
- "Here are the paths between elements of this type" (path constructors)
- (And paths between paths, etc. — higher path constructors for the higher-dimensional case)

The resulting type is the "free type" generated by these elements and paths — the smallest type containing the specified data.

## The Interval Type

The simplest non-trivial HIT is the interval $\mathbb{I}$:

**Definition 1.1 (Interval).** The interval type $\mathbb{I}$ is defined by:
- Point constructor: $0_\mathbb{I} : \mathbb{I}$
- Point constructor: $1_\mathbb{I} : \mathbb{I}$
- Path constructor: $\mathsf{seg} : 0_\mathbb{I} =_\mathbb{I} 1_\mathbb{I}$

So $\mathbb{I}$ has two specified points and one specified path between them.

**The eliminator for $\mathbb{I}$.** To define a function $f : \mathbb{I} \to B$, it suffices to specify:
- $f(0_\mathbb{I}) = b_0 : B$ (the value at the left endpoint)
- $f(1_\mathbb{I}) = b_1 : B$ (the value at the right endpoint)
- $\mathsf{ap}_f(\mathsf{seg}) = p : b_0 = b_1$ (the image of the path $\mathsf{seg}$)

Computation rules:
- $f(0_\mathbb{I}) \equiv b_0$ (definitional)
- $f(1_\mathbb{I}) \equiv b_1$ (definitional)
- $\mathsf{ap}_f(\mathsf{seg}) = p$ (propositional)

This says: to map out of the interval, choose where to send the two endpoints and the path between them. The path in $B$ can be anything — the interval is "flexible" in that sense.

**The dependent eliminator.** For $P : \mathbb{I} \to \mathsf{Type}$, a section $s : \prod_{x:\mathbb{I}} P(x)$ is determined by:
- $s(0_\mathbb{I}) : P(0_\mathbb{I})$
- $s(1_\mathbb{I}) : P(1_\mathbb{I})$
- $\mathsf{apd}_s(\mathsf{seg}) : \mathsf{transport}^P(\mathsf{seg}, s(0_\mathbb{I})) = s(1_\mathbb{I})$

## The Interval is Contractible

**Theorem 1.2.** $\mathbb{I}$ is contractible.

*Proof.* We show $\mathsf{isContr}(\mathbb{I})$ by finding a center $c : \mathbb{I}$ and contracting homotopy $h : \prod_{x:\mathbb{I}}(c = x)$.

Take $c = 0_\mathbb{I}$. Define $h : \prod_{x:\mathbb{I}}(0_\mathbb{I} = x)$ using the $\mathbb{I}$-eliminator:
- $h(0_\mathbb{I}) :\equiv \mathsf{refl}_{0_\mathbb{I}} : 0_\mathbb{I} = 0_\mathbb{I}$
- $h(1_\mathbb{I}) :\equiv \mathsf{seg} : 0_\mathbb{I} = 1_\mathbb{I}$
- $\mathsf{apd}_h(\mathsf{seg})$: we need $\mathsf{transport}^{0=(-)}(\mathsf{seg}, \mathsf{refl}_{0}) = \mathsf{seg}$

The transport computation: $\mathsf{transport}^{0=(-)}(\mathsf{seg}, q) = q \cdot \mathsf{seg}$ (transport in path types concatenates; see Chapter 16). So we need $\mathsf{refl}_0 \cdot \mathsf{seg} = \mathsf{seg}$, which holds by the left unit law.

So $h$ is well-defined, and $(0_\mathbb{I}, h)$ witnesses contractibility. $\square$

Wait — but $\mathbb{I}$ is contractible (equivalent to $\mathbf{1}$), so why is it interesting?

The interval is interesting not for what it *is* (contractible, hence trivial) but for what it can *do*. It gives a concrete type with a non-trivial path ($\mathsf{seg}$), and this path can be used as a "template" for other paths.

## The Interval and Function Extensionality

One important application of the interval: it provides an alternative proof of function extensionality.

**Theorem 1.3 (Interval $\Rightarrow$ funext).** If the interval type $\mathbb{I}$ exists, then function extensionality holds.

*Proof.* Let $f, g : A \to B$ with $H : \prod_{x:A} f(x) = g(x)$ (a pointwise equality). We want to show $f = g$.

Define $k : A \to \mathbb{I} \to B$ by:
- For each $x : A$: $k(x)(0_\mathbb{I}) = f(x)$, $k(x)(1_\mathbb{I}) = g(x)$, and the image of $\mathsf{seg}$ is $H(x)$

This is well-defined by the $\mathbb{I}$-eliminator applied at each $x$.

Now define $\tilde{k} : \mathbb{I} \to (A \to B)$ by $\tilde{k}(i)(x) = k(x)(i)$ (currying). Then:
- $\tilde{k}(0_\mathbb{I}) = \lambda x.\, k(x)(0_\mathbb{I}) = \lambda x.\, f(x) = f$
- $\tilde{k}(1_\mathbb{I}) = \lambda x.\, k(x)(1_\mathbb{I}) = \lambda x.\, g(x) = g$

So $\mathsf{ap}_{\tilde{k}}(\mathsf{seg}) : f = g$! The path $\mathsf{seg}$ in $\mathbb{I}$ maps to a path $f = g$ in $A \to B$.

More precisely: $\tilde{k} : \mathbb{I} \to (A \to B)$ maps $0_\mathbb{I}$ to $f$ and $1_\mathbb{I}$ to $g$. The image of $\mathsf{seg}$ under $\tilde{k}$ is a path $f = g$. $\square$

This is the conceptual proof: a homotopy from $f$ to $g$ gives a path in the interval that "translates" to a path $f = g$.

## The Circle $S^1$

The most important HIT in HoTT:

**Definition 1.4 (Circle).** The circle $S^1$ is defined by:
- Point constructor: $\mathsf{base} : S^1$
- Path constructor: $\mathsf{loop} : \mathsf{base} =_{S^1} \mathsf{base}$

So $S^1$ has one specified point and one specified loop at that point. The circle is the "free type with one point and one non-trivial loop."

**The non-dependent eliminator for $S^1$.** To define a function $f : S^1 \to B$, it suffices to specify:
- $f(\mathsf{base}) = b : B$ (where to send the base point)
- $\mathsf{ap}_f(\mathsf{loop}) = \ell : b = b$ (a loop in $B$ for the image of $\mathsf{loop}$)

Computation rules:
- $f(\mathsf{base}) \equiv b$
- $\mathsf{ap}_f(\mathsf{loop}) = \ell$ (propositional)

**The dependent eliminator for $S^1$.** For $P : S^1 \to \mathsf{Type}$, a section $s : \prod_{x:S^1} P(x)$ is determined by:
- $s(\mathsf{base}) = b : P(\mathsf{base})$
- $\mathsf{apd}_s(\mathsf{loop}) = \ell : \mathsf{transport}^P(\mathsf{loop}, b) = b$ (a "loop-over-$b$" in the fiber)

This is the most general form: to define a dependent function on $S^1$, specify what happens at the base point and at the loop (with the appropriate transport condition).

## What the Loop Means

The path constructor $\mathsf{loop} : \mathsf{base} = \mathsf{base}$ is a non-trivial loop. But is it really non-trivial — is $\mathsf{loop} \neq \mathsf{refl}_\mathsf{base}$?

Yes! If $\mathsf{loop} = \mathsf{refl}_\mathsf{base}$, then $S^1$ would be contractible (the only loop at $\mathsf{base}$ is reflexivity, so the entire type is contractible). But $S^1$ is not contractible — its fundamental group is $\mathbb{Z}$, as we'll prove.

The proof that $\mathsf{loop} \neq \mathsf{refl}$ uses the non-trivial cover of $S^1$ (the universal cover) and the encoding function. In fact, $\mathsf{loop}^n \neq \mathsf{loop}^m$ for $n \neq m$ — there are infinitely many distinct loops at $\mathsf{base}$.

## Maps Out of the Circle

The elimination rule for $S^1$ says: a map out of $S^1$ to $B$ is the same as a "based loop" in $B$ — a point $b : B$ together with a loop $\ell : b = b$.

**Example 1.5 (Identity).** The identity map $\mathsf{id}_{S^1} : S^1 \to S^1$ corresponds to $(\mathsf{base}, \mathsf{loop})$ — send the base point to itself, and the loop to itself.

**Example 1.6 (Constant map).** The constant map $\mathsf{const}_b : S^1 \to B$ corresponds to $(b, \mathsf{refl}_b)$ — send the base point to $b$, and the loop to the trivial loop $\mathsf{refl}_b$.

**Example 1.7 (Winding number maps).** For any $n : \mathbb{Z}$, the "winding $n$ times" map $w_n : S^1 \to S^1$ corresponds to $(\mathsf{base}, \mathsf{loop}^n)$ — send the base point to itself, and the loop to $n$ copies of $\mathsf{loop}$ (concatenated).

These maps capture the "degree" of a circle map in classical algebraic topology.

**Example 1.8 (The universal cover).** The universal cover of $S^1$ is the type $\tilde{S}^1$ with:
- Elements: $\sum_{x:S^1}(\mathsf{base} = x)$ — pairs of a point and a path from the base
- The fiber over $\mathsf{base}$ is $\mathsf{base} = \mathsf{base}$ — the loop space

By the fundamental theorem of covering spaces, the universal cover of $S^1$ should be $\mathbb{R}$ (the real line, as a covering space via the exponential map $t \mapsto e^{2\pi i t}$). In the discrete setting, it's $\mathbb{Z}$ (the fiber over the base). We'll see this in the $\pi_1(S^1) = \mathbb{Z}$ computation.

## The Loop Space of the Circle

The key property of $S^1$:

**Theorem 1.9 (First homotopy group of the circle).** $\Omega(S^1, \mathsf{base}) = (\mathsf{base} =_{S^1} \mathsf{base}) \simeq \mathbb{Z}$.

This is the fundamental computation of HoTT, proved using the encode-decode method (Chapter 20). The key ingredients:
- The HIT definition of $S^1$ (this chapter)
- The integers $\mathbb{Z}$ with their successor equivalence
- Univalence (to define the code family over $S^1$ using the successor equivalence)

The proof establishes a bijection between loops in $S^1$ and integers: $\mathsf{loop}^n$ corresponds to $n \in \mathbb{Z}$.

## The Circle in Homotopy Theory

The circle $S^1$ is the most important type in HoTT beyond the basic type formers. It's:
- The first space with non-trivial $\pi_1$: $\pi_1(S^1) = \mathbb{Z}$
- The 1-sphere in the sequence $S^0 = \mathsf{Bool}$, $S^1$, $S^2$, ...
- The base case for the Freudenthal suspension theorem
- The source of the Hopf fibration (via $S^1 * S^1 = S^3 \to S^2$)

Every computation in synthetic homotopy theory either involves the circle directly or uses methods developed for the circle.

## Formalizing HITs

In practice, HITs must be handled carefully in proof assistants:

**In Lean 4:** The circle is defined using `Quot` or `Quotient` types (which are a special case of HITs for propositional truncation). General HITs are not directly supported in Lean 4's core, but can be simulated via quotients with care.

**In Agda with `--cubical`:** General HITs are natively supported. The circle is:
```agda
data S¹ : Type where
  base : S¹
  loop : base ≡ base
```

The computational content of HITs (how to compute with `loop`) is handled by Cubical Agda's interval type.

**In HoTT Book Agda:** HITs are axiomatized using postulates, with the eliminator and computation rules stated as postulates.

The cleanest computational behavior comes from cubical type theory (Chapter 23), where HITs are genuine type-theoretic constructions with definitional computation rules.
