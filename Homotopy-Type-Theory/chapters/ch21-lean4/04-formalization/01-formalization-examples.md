# 4.1 Formalization Projects

## From Mathematics to Machine-Verified Proofs

Formalizing mathematics in Lean 4 is a different activity from writing a textbook proof. A textbook proof is a *sketch* — it gives the key ideas and trusts the reader to fill in the rest. A formal proof must be *complete* — every step must be checkable by the type checker.

This is harder but also more rewarding. When Lean accepts your proof, you know it's correct — not "probably correct" or "correct modulo routine verifications," but definitively correct within the chosen axiom system.

This section walks through three guided formalization projects, each connecting to material from our curriculum.

## Project 1: Formalizing Group Theory Background

### Goal: Prove the First Isomorphism Theorem

The first isomorphism theorem says: if $\phi : G \to H$ is a group homomorphism, then $G / \ker(\phi) \cong \phi(G)$.

This is the algebraic background for understanding why $\pi_1(S^1) = \mathbb{Z}$: the covering space map gives a homomorphism, and the first isomorphism theorem identifies the quotient.

```lean
import Mathlib.GroupTheory.QuotientGroup
import Mathlib.GroupTheory.GroupAction.Basic

-- The setup: a group homomorphism
variable {G H : Type*} [Group G] [Group H] (φ : G →* H)

-- The kernel: elements mapping to 1
-- Already in Mathlib as:
#check MonoidHom.ker  -- φ.ker : Subgroup G

-- The image: elements in the range
#check MonoidHom.range  -- φ.range : Subgroup H

-- The first isomorphism theorem is:
#check QuotientGroup.quotientKerEquivRange
-- QuotientGroup.quotientKerEquivRange :
--   G ⧸ φ.ker ≃* φ.range

-- Let's use it:
example (φ : G →* H) : G ⧸ φ.ker ≃* φ.range :=
  QuotientGroup.quotientKerEquivRange φ
```

That was easy — the theorem is already in Mathlib. Let's prove a consequence ourselves.

```lean
-- Corollary: if ker(φ) = {1}, then φ is injective
theorem injective_of_trivial_ker (φ : G →* H)
    (hker : φ.ker = ⊥) : Function.Injective φ := by
  -- Rewrite: injective ↔ ker = {1}
  rw [← MonoidHom.ker_eq_bot_iff]
  exact hker

-- This is actually already in Mathlib:
#check MonoidHom.ker_eq_bot_iff
-- MonoidHom.ker_eq_bot_iff : φ.ker = ⊥ ↔ Function.Injective φ
```

### A From-Scratch Group Proof

Let's prove something more elementary: in a group, the inverse of a product is the product of inverses in reverse order.

```lean
theorem mul_inv_rev {G : Type*} [Group G] (a b : G) :
    (a * b)⁻¹ = b⁻¹ * a⁻¹ := by
  -- Strategy: show that (b⁻¹ * a⁻¹) * (a * b) = 1
  -- Then uniqueness of inverses gives the result
  apply eq_of_mul_eq_one_left  -- or use the more direct approach
  calc b⁻¹ * a⁻¹ * (a * b)
      = b⁻¹ * (a⁻¹ * a) * b := by group
    _ = b⁻¹ * 1 * b         := by rw [mul_left_inv]
    _ = b⁻¹ * b             := by rw [mul_one]
    _ = 1                   := by rw [mul_left_inv]

-- But there's a much shorter proof using the "group" tactic:
theorem mul_inv_rev' {G : Type*} [Group G] (a b : G) :
    (a * b)⁻¹ = b⁻¹ * a⁻¹ := by
  group  -- the "group" tactic normalizes group expressions
```

The `group` tactic is to group theory what `ring` is to rings — it proves equalities that hold in any group by normalization.

## Project 2: The Integers as a Group

The integers $\mathbb{Z}$ are the fundamental example connecting algebra to topology (since $\pi_1(S^1) = \mathbb{Z}$). Let's formalize their key properties.

### $\mathbb{Z}$ as a cyclic group

The integers $\mathbb{Z}$ are the unique infinite cyclic group: generated by 1, with no relations.

```lean
import Mathlib.Data.Int.Basic
import Mathlib.GroupTheory.SpecificGroups.Cyclic

-- ℤ is an additive commutative group
#check (inferInstance : AddCommGroup ℤ)

-- It's cyclic, generated by 1
example : ∀ n : ℤ, n ∈ AddSubgroup.closure ({1} : Set ℤ) := by
  intro n
  rw [AddSubgroup.mem_closure_singleton]
  -- The closure of {1} is {n * 1 | n : ℤ}... this needs some thought
  exact ⟨n, by ring⟩

-- The successor function as an automorphism
def succEquiv : ℤ ≃+ ℤ where
  toFun    := (· + 1)
  invFun   := (· - 1)
  left_inv := fun n => by ring
  right_inv := fun n => by ring
  map_add' := fun n m => by ring

-- This is an automorphism of ℤ as an additive group
#check succEquiv  -- : ℤ ≃+ ℤ
```

### The winding number as a group homomorphism

In HoTT, the winding number is the isomorphism $\pi_1(S^1) \cong \mathbb{Z}$. We can formalize its group homomorphism property:

```lean
-- The winding number satisfies: wind(p · q) = wind(p) + wind(q)
-- In Mathlib terms, the fundamental group of the circle has a specific description

-- The fundamental group of the circle is ℤ
-- (This requires topology, but the statement is in Mathlib)
import Mathlib.Topology.Covering  -- covering space theory

-- π₁(S¹) ≅ ℤ as groups
-- The map wind : π₁(S¹) → ℤ is a group homomorphism
-- wind([p · q]) = wind([p]) + wind([q])
-- This is essentially the content of the fundamental theorem about the circle
```

## Project 3: Category Theory for HoTT

### Groupoids as categories

A groupoid is a category where every morphism is an isomorphism. The fundamental groupoid $\Pi_1(X)$ of a topological space has:
- Objects: points of $X$
- Morphisms: homotopy classes of paths

In HoTT, every type is a $\infty$-groupoid, with paths as morphisms, homotopies between paths as 2-morphisms, etc.

Let's formalize the basic groupoid structure:

```lean
import Mathlib.CategoryTheory.Groupoid

-- A groupoid
class Groupoid (C : Type u) extends CategoryStruct C where
  inv : ∀ {X Y : C}, (X ⟶ Y) → (Y ⟶ X)
  inv_comp : ∀ {X Y : C} (f : X ⟶ Y), inv f ≫ f = 𝟙 X
  comp_inv : ∀ {X Y : C} (f : X ⟶ Y), f ≫ inv f = 𝟙 Y

-- The fundamental groupoid of a topological space
#check FundamentalGroupoid
-- FundamentalGroupoid : TopologicalSpace α → Groupoid (FundamentalGroupoid α)

-- Objects are points, morphisms are homotopy classes of paths
#check FundamentalGroupoid.Hom
```

### Functors and natural transformations

A functor between categories preserves the categorical structure. Functoriality is exactly the `ap` (action on paths) operation from Chapter 16:

```lean
-- In type theory, every function f : A → B induces a "functor"
-- on path spaces:
-- ap f : (a₁ = a₂) → (f a₁ = f a₂)

-- In Mathlib's category theory:
#check Functor.map          -- F.map : (X ⟶ Y) → (F.obj X ⟶ F.obj Y)
#check Functor.map_id       -- F.map (𝟙 X) = 𝟙 (F.obj X)
#check Functor.map_comp     -- F.map (f ≫ g) = F.map f ≫ F.map g

-- These are exactly the ap_refl and ap_compose laws from HoTT!
```

A natural transformation between functors is the categorical analogue of a homotopy between functions:

```lean
-- NatTrans.app : ∀ X, F.obj X ⟶ G.obj X
-- The naturality square commutes: for f : X ⟶ Y,
-- F.map f ≫ η.app Y = η.app X ≫ G.map f

-- In type theory:
-- A homotopy H : f ~ g : A → B gives
-- H : ∀ (x : A), f x = g x
-- with the naturality square: ap f p ▷ H y = H x ◁ ap g p
-- (for p : x = y in A)
```

### The category of types

The category `Type` (all types as objects, functions as morphisms) is a key example:

```lean
import Mathlib.CategoryTheory.Types

-- Types form a category
example : Category (Type u) := inferInstance

-- Isomorphisms in Type are equivalences (bijections)
#check CategoryTheory.Iso  -- X ≅ Y means f : X → Y with g : Y → X inverse

-- In HoTT, equivalences A ≃ B correspond to Iso A B
-- (though HoTT distinguishes between different notions of equivalence)
```

## Project 4: Connecting to HoTT Themes

### Quotient types

Lean 4's quotient types (built into the core) correspond to setoid quotients — truncated versions of the HoTT colimits:

```lean
-- A setoid: a type with an equivalence relation
structure Setoid (α : Type u) where
  r : α → α → Prop
  iseqv : Equivalence r

-- The quotient type
-- Quotient.mk : α → Quotient s  (constructor)
-- Quotient.lift : (f : α → β) → (∀ a b, s.r a b → f a = f b) → Quotient s → β

-- Example: the integers as a quotient of pairs of naturals
def IntAsQuotient : Type := Quotient (r := fun (a b : ℕ × ℕ) => a.1 + b.2 = b.1 + a.2)
-- (a₁, a₂) ~ (b₁, b₂) iff a₁ - a₂ = b₁ - b₂ (as integers)
-- This is the standard construction of ℤ from ℕ
```

In HoTT terms, this is the 0-truncated pushout (set-quotient). The HIT version would be the non-truncated colimit.

### Propositional truncation

Lean 4's `Nonempty` type is propositional truncation:

```lean
-- Nonempty α: "there exists an element of α" (proof-irrelevant)
#check Nonempty          -- Nonempty : Type u → Prop
#check Nonempty.intro    -- Nonempty.intro : α → Nonempty α
#check Nonempty.elim     -- Nonempty.elim : Nonempty α → (α → Prop) → Prop
                         -- Only eliminates into Prop, not Type

-- This is exactly the propositional truncation ‖A‖ from Chapter 17!
-- ‖A‖ → P (where P : Prop) is allowed
-- ‖A‖ → B (where B : Type) is not (without further assumptions)
```

### Type equivalences

Lean 4's `Equiv` type is close to the HoTT equivalence type:

```lean
import Mathlib.Logic.Equiv.Basic

-- Equiv α β: a bijection between α and β
structure Equiv (α β : Sort*) where
  toFun    : α → β
  invFun   : β → α
  left_inv : ∀ x, invFun (toFun x) = x
  right_inv : ∀ y, toFun (invFun y) = y

-- This is the "quasi-inverse" notion: qinv(f) from Chapter 18
-- In Lean 4's Prop-based setting, this is fine because
-- the coherence issue disappears (all proofs of a Prop are equal)

-- Key equivalences:
#check Equiv.sumComm    -- α ⊕ β ≃ β ⊕ α
#check Equiv.prodComm   -- α × β ≃ β × α
#check Equiv.sigmaAssoc -- Σ (Σ a, P a) Q ≃ Σ a, Σ (P a), Q
```

## A Complete Formalization: Proving a Simple HoTT-Adjacent Theorem

Let's formalize a complete theorem: **the image of a group homomorphism is a subgroup**.

```lean
import Mathlib.GroupTheory.Subgroup.Basic
import Mathlib.GroupTheory.Hom.Group

variable {G H : Type*} [Group G] [Group H]

-- We want to prove: φ.range is a subgroup of H
-- This is already done for us:
#check MonoidHom.range          -- : G →* H → Subgroup H
#check MonoidHom.range_restrict -- : G →* φ.range

-- But let's prove the key properties ourselves, as an exercise:

-- 1. The range contains the identity
theorem range_contains_one (φ : G →* H) : (1 : H) ∈ φ.range := by
  rw [MonoidHom.mem_range]
  exact ⟨1, φ.map_one⟩  -- φ(1) = 1

-- 2. The range is closed under multiplication
theorem range_mul_closed (φ : G →* H) (h₁ h₂ : H)
    (h₁_in : h₁ ∈ φ.range) (h₂_in : h₂ ∈ φ.range) :
    h₁ * h₂ ∈ φ.range := by
  rw [MonoidHom.mem_range] at *
  obtain ⟨g₁, rfl⟩ := h₁_in
  obtain ⟨g₂, rfl⟩ := h₂_in
  exact ⟨g₁ * g₂, φ.map_mul g₁ g₂⟩

-- 3. The range is closed under inverses
theorem range_inv_closed (φ : G →* H) (h : H) (h_in : h ∈ φ.range) :
    h⁻¹ ∈ φ.range := by
  rw [MonoidHom.mem_range] at *
  obtain ⟨g, rfl⟩ := h_in
  exact ⟨g⁻¹, φ.map_inv g⟩
```

This is a complete, machine-verified proof of a standard result. Each step is explicit, the types are checked, and there's no room for gaps.

## The Experience of Formalizing

Working through a formalization project teaches you several things that textbook proofs conceal:

**1. Where the real work is.** In a textbook proof of $\pi_1(S^1) = \mathbb{Z}$, the hard part is "the encode and decode maps are inverses." In Lean, you discover that half the work is *defining* the code family correctly so that definitional equality handles the computational steps.

**2. What's actually being assumed.** Every `import` introduces axioms and definitions. When you prove something "in Mathlib," you're proving it assuming `propext`, `funext`, quotient types, and choice — the standard Lean 4 axioms. These are all classical-mathematics compatible but different from pure MLTT.

**3. The gap between Lean 4 and HoTT.** Some things that seem like they should work — defining HITs, modeling the circle, computing $\pi_1(S^1)$ synthetically — simply can't be done in Lean 4. The K axiom for Prop means all of Lean 4's types behave like sets for equality purposes. This isn't a bug; it's a feature for classical mathematics. But it means the HoTT-specific content belongs in Cubical Agda.

**4. The joy of automation.** When `ring`, `simp`, or `exact?` closes a goal you were dreading, the feeling is real. Lean's automation is genuinely powerful, and learning to use it well is a craft.

## Next Steps for Formalization

Some formalization projects that connect directly to our curriculum:

**Beginner:**
- Prove basic properties of the integers (Euclidean division, GCD, primality)
- Formalize the group axioms and derive consequences (uniqueness of identity, uniqueness of inverse)
- Prove that group homomorphisms preserve inverses and the identity

**Intermediate:**
- Formalize the definition of a groupoid and prove basic properties
- Work with Mathlib's `FundamentalGroupoid` and its homotopy groups
- Prove the first isomorphism theorem from scratch (without using Mathlib's version)

**Advanced:**
- Formalize the Van Kampen theorem using Mathlib's topology and group theory
- Work with simplicial sets in Mathlib's `CategoryTheory.SimplicialObject`
- Contribute a new theorem to Mathlib (the community is welcoming and has good documentation for contributors)

**HoTT-specific (in Cubical Agda, not Lean 4):**
- Formalize $\pi_1(S^1) = \mathbb{Z}$ using the encode-decode method
- Prove the Freudenthal suspension theorem
- Compute $\pi_n(S^n) = \mathbb{Z}$

The division is clear: Lean 4 for the classical background, Cubical Agda for the HoTT-specific content. Between the two tools, the entire curriculum is formalizable.
