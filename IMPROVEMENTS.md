## 1. Executive summary

The library is in far better shape on **content** than on **tooling**. Across ~10,000 markdown files (~8 million words), the prose is uniformly finished, dense, and publishable — spot-reads at the beginning, middle, and end of every book found no stubs, placeholders, or abrupt endings, with exactly two exceptions (PhotonicComputing's second half and Theorem-Proving's ch16–22, both scaffolded but unwritten).

The tooling around that content, however, is largely broken or disconnected:

1. **No quiz app in the repo can currently serve its question bank.** The Rust loaders expect flat JSON arrays, but every bank stores one question per file; the one bundled sample file (ReservoirComputing) uses an incompatible schema that fails deserialization. Even Homotopy-Type-Theory's 1,423-question bank is unloadable as-is.
2. **12 of 14 books have essentially no questions anyway** (1–2 seed files each). Only HoTT (1,423) and ReservoirComputing (97, in the wrong place/schema) have real banks.
3. **6 of 14 `subject.toml` files point at chapter files that don't exist**, so the quiz generator couldn't read those books' content even if it were invoked — and it never is: the CLI reimplements its own engine and the Anthropic-powered generator in `quiz-core` is dead code.
4. **7 of 14 PDF build scripts silently omit most of the book** (non-recursive directory walks that miss deeply nested chapters — in the worst cases dropping ~450K of ~490K words).
5. **The quiz app is one product copied byte-identically 14 times** (~65K duplicated LOC), while the build script forked into 13+ divergent copies — the exact inverse of what you want (share the code, vary the config).

The root README's stated goal is "a process for generating text, tutorials, labs, quizzes… workflows that automatically generate new material." The single highest-leverage move is to **make that process explicit**: one shared quiz-app workspace, one config-driven book builder, one question schema, and a repo-wide `validate` script run in CI. Most of the defects below would have been caught by a 50-line validation script (a prototype of that check — resolving every `subject.toml` chapter path — is what surfaced finding #3).

## 3. Cross-cutting issues

### 3.1 The quiz system doesn't work end-to-end (highest priority)

The repo ships 14 identical Rust quiz workspaces (`quiz-cli`, `quiz-tui`, `quiz-web` over a shared `quiz-core`), but four independent breaks mean no book delivers a working adaptive quiz:

**(a) Question banks are empty.** Per-book counts of question JSON files:

| Book | Questions | Book | Questions |
|---|---|---|---|
| Homotopy-Type-Theory | **1,423** | Abstract-Algebra | **0** (no `questions/` at all) |
| ReservoirComputing | 2 (+97 in `quiz-app/questions/sample.json`, wrong schema) | Computational-Systems-Synthetic-Biology | **0** |
| BasalCognition | 2 | All 10 remaining books | **1 each** |

**(b) The loaders can't read the banks that do exist.** `quiz-core/src/question.rs` offers `load_question_pool` (expects a **flat JSON array** per file, scans one directory non-recursively) and `load_quiz` (expects a `{title, questions[]}` object). The banks store **one object per file** under `questions/chNN/`, so they silently fail to load — including HoTT's 1,423 files. Meanwhile `ReservoirComputing/quiz-app/questions/sample.json` uses `{type: "multiple_choice", correct: N}` where `Question` requires `{kind: "mc", answer: N}`, so quiz-tui and quiz-web (which default to loading exactly that file) fail to deserialize at runtime.

**(c) The engine is dead code.** `quiz-cli` (1,370 LOC) imports only the `Question` type from quiz-core and **reimplements** its own profile, mastery, RNG, and question selection (`quiz-cli/src/main.rs:118-469`) — with different constants (initial mastery 0.5 vs quiz-core's 0.30) and a different profile store (`~/.local/share/quiz-rc/` vs quiz-core's `data/profiles/`). Consequently `quiz-core`'s `generator.rs` (the Anthropic API question generator), `adaptive.rs`, `mastery.rs`, `profile.rs`, `storage.rs`, and `config.rs` are **never called by any binary**. The advertised adaptive/generative behavior is unreachable.

**(d) The per-book config is broken in 6 books.** Validating every `subject.toml` chapter path against disk:

| Book | Chapters resolving | Problem |
|---|---|---|
| Epistemology | 0/10 | Points at `NN_*/README.md`; real files are `00-unit-survey.md` |
| Metaphysics | 0/13 | Points at `NN_*/README.md`; real files are `00_introduction.md` / `00-domain-survey.md` |
| PhilosophyOfMind | 0/20 | Points at `NN_*/README.md`; real files are `00-unit-introduction.md` |
| PhilosophyOfTime | 0/12 | Points at `unit-*/README.md`; real files are `intro.md` |
| PhotonicComputing | 0/14 | Points at `ch00-fundamentals/…ch13-frontiers/README.md` — a layout that no longer exists |
| Theorem-Proving | 9/22 | 13 chapters referenced without the `textbook/` prefix |
| Other 8 books | all resolve | — |

**Additional quiz-app defects:**
- Every copy hardcodes **"Reservoir Computing"** branding — CLI banner, data dir `quiz-rc`, and a fallback questions path naming `ReservoirComputing/quiz-app/questions` (`quiz-cli/src/main.rs:1-7, :247, :506, :1154`). Nothing reads the book title from `subject.toml`.
- **Builds fail on a clean machine**: `quiz-core` uses `reqwest` with default native TLS → `openssl-sys` build failure without system OpenSSL headers (verified on this Fedora machine). Fix: `reqwest = { version = "0.12", default-features = false, features = ["blocking", "json", "rustls-tls"] }`.
- **Zero Rust tests** across all 14 copies. The only tests in the repo (`Abstract-Algebra/tests/*.py`, 6 files) target a deleted Python `quiz_app` package and fail at import.
- The generator pins `claude-sonnet-4-6` (`generator.rs:35`). That ID is valid and currently served, but one generation behind (`claude-sonnet-5` is current) — make the model configurable (env var or `subject.toml`) instead of a compile-time constant.
- `BasalCognition/quiz-app/src/{main.rs,questions.rs}` are orphans from a pre-workspace single-binary version (the workspace manifest doesn't include them); the 72KB embedded bank in `questions.rs` uses yet another schema.
- `Cargo.lock` committed for 9 of 14 quiz-apps, absent for 5. For binary crates it should be committed uniformly.
- No quiz-app has a README; run instructions exist nowhere (`QUIZ_APP.md` documents the deleted Python app).

**Suggested fix sequence:** (1) unify on the HoTT question schema and teach the loaders to read one-object-per-file chapter dirs recursively (or add a pack step that assembles per-chapter arrays); (2) fix the 6 broken `subject.toml` files — mostly one `sed`-able path pattern per book; (3) rewire `quiz-cli` onto quiz-core's engine, deleting the ~700-LOC duplicate and thereby activating adaptive selection + generation; (4) de-brand via `subject.toml`; (5) switch to rustls; (6) port the orphaned Python tests to Rust against quiz-core. Then (7) bulk-generate banks for the 12 empty books — the HoTT pipeline and per-book `system_prompt`s already written in every `subject.toml` show this was the plan.

### 3.3 One app copied 14×; one script forked 13×

- `quiz-app/` is byte-identical across all 14 books except `subject.toml` (verified by checksum — every `.rs` and `Cargo.toml` matches). That's ~4,600 LOC × 14 ≈ 65K duplicated lines; any bug fix currently needs 14 commits.

## Appendix — How findings were verified

- **Duplication:** md5 checksums across all 14 `quiz-app/` trees (every `.rs`/`Cargo.toml` identical; only `subject.toml` differs); `diff -rq` for CSSB ch3.7.
- **subject.toml validation:** script resolving every `chapters[].file` against `chapters_dir` for all 14 books (results in §3.1d).
- **Build failure:** `cargo check` on `PhilosophyOfTime/quiz-app` → `openssl-sys` failure (no system OpenSSL headers).
- **Question counts:** `find */questions -name '*.json'` + JSON parsing; schema fields read from `Homotopy-Type-Theory/questions/ch00-logic-and-proof/001.json`, seeds, and `sample.json`.
- **Dead code / loader mismatch:** read of `quiz-core/src/{question,generator,adaptive,mastery,profile,storage,config}.rs` and all three binary `main.rs` files; grep for quiz-core imports across binaries.
- **Content completeness:** spot-reads at start/middle/end of chapters in all 14 books; zero-byte census for PhotonicComputing (318/603); TODO/placeholder greps (all hits false positives except the two books flagged).
- **Build coverage:** per-script traversal analysis (`iterdir()` vs `rglob`) cross-checked against on-disk nesting; GR duplicate-unit census (20 unit dirs for 16 units).
- **Model ID:** `claude-sonnet-4-6` confirmed valid/active (Sonnet 4.6); current Sonnet is `claude-sonnet-5`.
