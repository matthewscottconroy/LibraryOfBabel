# 20.5.2 Surface Codes on Photonic Graph States

## Foliating a Code into a Cluster

The surface code is the workhorse of fault tolerance: a topological stabilizer code on a 2D lattice, correcting errors by measuring local $X$- and $Z$-type parity checks, with one of the highest known thresholds and only nearest-neighbour interactions. Circuit-model platforms run it by repeating a syndrome-extraction circuit in time. Photonics runs it differently — and, arguably, more naturally — because MBQC (Section 20.3) already *is* measurement-based. Raussendorf, Harrington, and Goyal (2007) showed that a particular three-dimensional cluster state, the **RHG lattice**, has the property that measuring its qubits sheet by sheet in the $X$ basis *implements the surface code in $(2{+}1)$ dimensions*: two spatial dimensions carry the code, and the third, swept out by the measurement schedule, plays the role of time. Stacking a 2D code into a 3D graph state this way is called **foliation**, and any Calderbank-Shor-Steane code can be foliated into a fault-tolerant cluster whose measurement pattern extracts its syndromes automatically (Bolt et al., 2016). The topological protection of Dennis, Kitaev, Landahl, and Preskill (2002) — errors must form lattice-spanning chains to cause a logical failure — is thereby inherited by a purely photonic, measure-as-you-go machine.

The fit is deep, not cosmetic. In the circuit model, syndrome extraction is an *extra* subroutine bolted onto the computation; in foliated MBQC, the measurements that *run* the algorithm and the measurements that *correct* it are the same measurements. FBQC (Section 20.3.3) exploits exactly this: its fusion networks are engineered so that fusion outcomes directly report the code's checks, folding error correction into the resource-consumption flow rather than layering it on top.

**The RHG lattice up close.** Concretely, the RHG cluster is a 3D graph state on a lattice with qubits arranged on the faces and edges of cubic cells; measuring every qubit in the $X$ basis yields a syndrome history from which a decoder — typically minimum-weight perfect matching — infers the most likely error chain. A logical failure requires an undetected error string spanning the lattice, an event whose probability falls exponentially in the code distance. Because the third dimension is *time* swept out by measurement, a photonic machine never holds the whole 3D state at once: it generates and measures one 2D sheet per clock cycle, streaming the lattice through fixed hardware — exactly the mode of operation the fusion networks of Section 20.3.3 realize.

## Loss Tolerance Built into the Graph

Foliation handles Pauli errors; photonic codes must also handle erasure. The decisive idea is Varnava, Browne, and Rudolph's (2006) **loss-tolerant one-way computation via counterfactual error correction**. Encode each logical qubit of the cluster not in one photon but in a **tree cluster** of photons, so that if a photon is lost, the parity of a branch of the tree can be measured indirectly through its still-surviving relatives — the information the lost photon carried is inferred rather than read. With sufficiently large trees this scheme tolerates photon-loss rates asymptotically approaching $50\%$ — the fundamental ceiling for the pure-loss (erasure) channel, since correcting more than half of all losses would let the lost half be reassembled elsewhere in violation of no-cloning. Practical codes sit well below that ceiling, but it establishes that loss, being located, admits thresholds no unlocated error could.

Combining the two error types is where real thresholds live. A photonic fault-tolerant architecture must simultaneously survive a Pauli rate $p$ and a loss rate $\ell$, and the achievable region is a trade-off curve: more loss tolerance can be bought at the price of less Pauli tolerance, and vice versa. The RHG/foliated surface-code family and its fusion-network descendants place the operating point at loss rates of a few percent to $\sim 10\%$ per photon together with sub-percent Pauli error — the target the hardware of Section 20.5.3 is built to hit.

## Worked Example: Distance and the Cost of a Logical Qubit

**Exponential suppression.** Below threshold, a distance-$d$ surface code suppresses the logical error rate as

$$p_L \;\approx\; C\left(\frac{p}{p_{\text{th}}}\right)^{\lfloor (d+1)/2 \rfloor},$$

where $p$ is the physical error rate, $p_{\text{th}}$ the threshold, and $C$ an $O(1)$ constant. The exponent is the number of physical errors needed to span the code — half its distance — which is the erasure advantage of Section 20.5.1 reappearing as a doubled exponent whenever errors are located.

**Sizing a code.** Take a physical error rate $p = 10^{-3}$ and threshold $p_{\text{th}} = 10^{-2}$, so $p/p_{\text{th}} = 0.1$, and demand an algorithm-scale logical error $p_L = 10^{-15}$. Setting $C = 1$,

$$0.1^{\,(d+1)/2} = 10^{-15} \;\Longrightarrow\; \frac{d+1}{2} = 15 \;\Longrightarrow\; d = 29.$$

A rotated planar surface code of distance $d$ uses $\approx d^2$ physical qubits, so each logical qubit costs $\approx 29^2 \approx 840$ physical qubits — and in the *foliated* 3D realization, that 2D footprint is swept through time, so the cluster-state cost per logical qubit per code cycle scales as $O(d^3) \sim 2\times 10^4$ photons. This is the multiplier behind Section 20.5.3's million-qubit figures: a machine running $\sim 10^3$ logical qubits at distance $\sim 30$ must marshal on the order of $10^7$ physical modes at any instant and stream $O(d^3)$ photons through each per cycle. The exercise makes concrete why the entire photonic effort reduces to two numbers — keep $p$ and $\ell$ below threshold, and keep $d$ (hence the photon budget) as small as the target logical error allows. Everything in Section 20.5.3 — sources, switches, detectors, interleaving — is engineering in service of exactly those two numbers.
