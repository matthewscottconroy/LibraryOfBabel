# Tracing by Hand

Two lessons on following a program yourself, without running it.

The state table is the tool: a row per step, a column per variable, filled in by
executing the program in your head and writing down what changes. It is tedious
and it is the single best way to convert a vague sense of what code does into an
accurate one.

The second lesson is desk checking — using a trace deliberately, to find a bug or
to convince yourself a loop is right before you run it. Chapter 9's invariants
and this technique are complementary: the invariant is the claim, and a trace is
how you check the claim when it is not obvious.
