# When It Goes Wrong

Three lessons on the failure you did not prevent.

First, reading a Java error properly — a stack trace carries far more information
than most beginners take from it, including the exact line, the chain of calls
that reached it, and frequently the cause in plain words. Learning to read one
carefully is the highest-return few minutes in this chapter.

Then bisection: the systematic way to find a bug, which converts an unbounded
search into about a dozen questions no matter how large the program is.

Then the debugger, which does what printing does without the printing, and a
short argument about when each is the better tool.
