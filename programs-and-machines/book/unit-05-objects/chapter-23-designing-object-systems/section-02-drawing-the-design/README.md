# Drawing the Design

There was a period when serious people believed programs would be drawn rather than
written, and a substantial industry grew up around the belief. It did not work, and
the wreckage gave diagrams a bad name that they partly deserve and partly do not.

What survived is small, cheap, and genuinely useful, and this section is about
separating it from what did not.

Two lessons.

A little UML, treated as a way of thinking on paper rather than as documentation
to maintain. Then a design worked all the way through — from a sentence of
requirements to running code — with the wrong turns left in, because those are the
part worth watching.
