# The Halting Problem

Everything in this book so far has been about what programs can do. This is the
other thing.

There is a question about programs — a plain one, that a working programmer might
genuinely want answered — for which no program can be written. Not a slow program,
not a difficult one: none, in any language, on any machine, however fast, however
clever, ever.

The proof is about a page, and you already have everything it needs.

Three lessons.

First the setup: what it means for a program to read a program, which Chapter 25
made concrete, and what exactly is being asked for. Then the contradiction, which
is short. Then the part that gets misreported — what undecidability actually
rules out, what it does not, and what practitioners do instead.
